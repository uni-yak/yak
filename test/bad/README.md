# test/bad

## 职责

负例语料：验证"禁止的事物必须被拒绝"。

## 组织

- 按拒绝规则分组，目录名与 `../../spec/proc/error.md` 错误码序列对应
- 每个负例指明：触发条件、对应规格文档、期望错误码

## 约定

- 每条规格中的"拒绝形态"至少有一个对应案例。
- 期望结果只接受明确的错误码与诊断结构，不接受模糊失败。
- 不得因实现困难而删除负例；如需调整必须先修订规格。

## 案例标记（机器可读，保持 ASCII 原文）

- `// expected_code: E<码>`：根必须被拒绝，命令退出 1；该码必须与目录名相同，且已在[错误码真源](../../spec/proc/error.def)登记。
- `// expected_diagnostics: <错误码> <错误码> ...`：声明完整诊断序列和顺序，至少含主错误码；省略时只期望一条主错误码。
- `// dependency: <文件名.yak>`：可重复。普通负例按声明顺序先编译成功依赖；图负例只将依赖复制到隔离源根，由扫描器读取。依赖不能兼作根，且必须被至少一个根引用。
- `// module_graph: scan`：图负例根标记，用正式入口扫描隔离源根并验证图；根与依赖不经过普通直链路径。
- `// module_graph: ambiguous <身份>`：图负例根标记，在两个独立源根各放一份同名依赖，要求只报 E4003。须声明唯一依赖 `<身份>.yak`，身份为只含 ASCII 字母、数字、下划线且不以数字开头的单段名称。
- `// spec: <规格锚点>`：对应的规格拒绝形态编号（R-x / OW-x / P-x / F-x 等）。
- 标记只放在源码头部；`// 触发：...` 是面向人的说明，不参与判定。

## 执行方式

普通负例用 `bash tools/link.sh [依赖单元 ...] <根用例> --out-dir <临时目录> --native-compiler <编译器.EXE> --no-run`。两遍均须退出 1、stdout 为空；原始流响应按字节偏移和错误码排序，完整诊断序列和汇总精确匹配，stderr 原样转发并标明失败的根。只允许保留诊断请求、响应及先前成功的依赖 `.iface` / `.obj`，依赖产物两遍同字节。根不得留下 `.obj` / `.iface` / `.ysm` 或最终 `.exe`；没有依赖的负例只允许诊断帧。未使用的局部绑定可能先触发 E4009，掩盖待测拒绝形态。

图负例由[候选门禁](../gate/README.md)用正式构建入口及各遍原生扫描器运行，禁用 Seed 回退。两遍均须退出 1、stdout 为空，终端 stderr 精确符合预期且两遍同字节；不得创建发布或审计目录。非歧义的图拒绝还校验结构化错误顺序及汇总。所有中间文件只写隔离临时目录。

数量上限的负例分别保留枚举变体、结构体字段和 ErrorSet 源码。ErrorSet 特意保留重复操作数，检查去重后仍有 65537 个不同成员。相邻合法边界和直接构造规范类型表的布局断言由[数量专项](../gate/README.md)维护。
