# test/ok

## 职责

正例语料：验证"允许的事物必须正确工作"。

## 组织

- 按语言特性分子目录：`lex/`、`type/`、`owner/`、`flow/`、`emit/` 等
- 每个子目录内的案例与 `../../spec/lang/` 文档对应

## 约定

- 每个根用例必须写明程序退出码和规格锚点；有规范输出时再断言标准输出。
- 一个案例只验证一个要点，不依赖上一次运行结果。
- 根和依赖同目录存放；依赖不能兼作根，且必须被至少一个根引用。

## 案例标记（机器可读，保持 ASCII 原文）

- `// expected_exit: <0-255>`：原生进程退出码，由[链接器](../../tools/link.sh)的 `--expect-exit` 断言。
- `// spec: <规格锚点>`：本例对应的规格章节；规格变更时同步核对案例。
- `// dependency: <文件名.yak>`：可重复；按头部声明顺序先编译依赖，再编译根。间接依赖也要列出，并置于使用它的单元之前。
- `// expected_stdout: <行>`：可重复。各行用 LF 连接，不自动加末尾 LF；额外的末尾空标记表示末尾 LF，单独一个空标记断言空输出。保留内容中的空白。未声明时不与固定字节比对，但 C2/C3 的原始 stdout、stderr 仍须一致。
- 标记只放在源码头部；其余中文注释不参与判定。

## 执行方式

`bash tools/link.sh [依赖单元 ...] <根用例> --out-dir <临时目录> --native-compiler <编译器.EXE> --expect-exit <码> [--expect-stdout <完整文本>]`。多行输出按一个参数传入；例如[有序多单元用例](emit/ordered_stdout_root.yak)的参数为 `--expect-stdout $'leaf\nmid\n'`。中间产物只写隔离临时目录，不写入语料目录。

[候选门禁](../gate/README.md)会分别使用 C2 与 C3 原生编译器执行全部正例，比较程序退出码和原始输出。动态数组字段投影[用例](owner/move_owning_field.yak)是正常通过的正例，不再标为预期失败。
