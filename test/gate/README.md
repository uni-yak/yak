# test/gate

## 职责

门禁用例：验证过程与产物层面的硬性判定。

## 脚本

| 脚本 | 判定什么 | 退出码 |
| --- | --- | --- |
| `t1_entry.sh` | T1 构建入口：带空格路径、可复现、失败回滚、模块图诊断、Seed 冻结对账、Yak COFF 审计对象的节与重定位（PE-2／PE-3）、实际链接器的跨节与外部 REL32 加数边界、单根对象与独立夹具的符号顺序（PE-4） | 0 通过 / 1 断言失败 / 2 环境不可用 / 3 并发 |
| `t1_base_matrix.sh` | base 子集在 T1 上的实配能力与拒绝形态；未实现项按缺口计数，不计入通过 | 同上；默认报告缺口；`--require-complete` 有缺口返回 1 |
| `t1_clean_gate.sh` | 构建只写登记位置、成功即清理、失败可回滚且可完全清理 | 同上 |
| `t1_linux_preflight.sh` | Linux 宿主上 T1 构建入口的前置条件（目标三元组、版本钉死、PE 运行器、Seed 冻结和运行时对象）；`--host-only` 仅检查宿主工具链 | 0 通过 / 1 存在阻塞 / 2 环境或参数无效 / 3 并发 |
| `t1_stage_boundary.py` | T1 组件边界（SD-1）：只允许 `compiler/full` 的三份已知说明和其目录；拒绝默认 `out/` 内的 full 可执行文件及归属标记。由 `compiler/min/verify.sh` 在构建前执行，不判断正式 T2 是否达成 | 0 通过 / 1 提前出现实体 / 2 无法检查 |
| `evidence.sh` | 生成可复现的取证报告（见 `EVIDENCE.md`） | 0 全通过 / 1 有失败记录 / 2 取证输入不可用 |
| `test_evidence_digest.sh` | 隔离检查源摘要、矩阵锁回收，以及发布级输入对账、双模式矩阵明细与完整记录 | 0 通过 / 非零失败 |
| `ci_record.sh` | 把一条命令记成 `.cmd/.log/.rc` 三件套，供 `evidence.sh --from-logs` 汇总 | 被记录命令的真实退出码 / 2 记录失败 |

本地自举使用 `test_min_self_parse.sh` 验证全部编译器源码可由 min 前端解析；`test_c0_stream_host.sh`、`test_c0_native_stdio.sh` 和 `test_c0_native_carrier.sh` 分别检查流帧、标准输入输出和 owning 载体的实际释放；`test_c0_native_ref.sh`、`test_c0_stack_abi.sh` 和 `test_c0_native_dynamic_record.sh` 检查跨单元引用、栈参数和动态数组投影（含缓冲迁移与 owning 覆盖）；`test_c0_native_slice.sh` 检查跨单元聚合切片的长度、元素步长与嵌套字段投影；`test_c0_ignite.sh` 用冻结 Seed 构造并对拍原生驱动，核对跨单元产物、执行和拒绝（含不发布）。这些本地断言不替代 T1 发布证据或 T2 三遍固定点。

[Linux 运行时桥专项](test_linux_runtime.sh) 可用 `bash test/gate/test_linux_runtime.sh` 在 Linux x86-64 原生运行。GNU as／ld 静态链接实际运行时与八份独立汇编观察器，核对可执行文件形态、入口对齐、栈与寄存器恢复、开放管道短读、完整写入、分配释放、服务失败和精确退出；两次汇编和基准两次链接须逐字节相同。此专项不验证 Yak 指令降级或正式 ELF 发布。

[通用 Linux base 定向门禁](test_base_linux_build.sh)在 Linux x86-64 上运行：`YAK_PE_RUNNER=wine bash test/gate/test_base_linux_build.sh 编译器.EXE 扫描器.EXE COFF运行时.OBJ`。按[构建规格](../../spec/proc/build.md)准备锁定工具链，先独立核验两枚 Win64 构建工具与 COFF 运行时的来源和摘要；ELF 运行时从源码构建，不取用该 COFF 对象。脚本检查前置与源码拒绝、同根 PE／ELF 审计镜像彼此隔离、Linux 原生输出和退出、无主另一格式不被接管，以及最终发布故障后旧 ELF、权限、归属与镜像恢复。按 `test/gate/tmp/base-linux-build.*` 保存实际命令、退出、诊断和产物。Wine 下的 PE 只用于兼容回归；此门禁不替代完整同 C2 双目标门禁、Win64 原生执行或可信 CI。

[Win64 栈 ABI 门禁](test_c0_stack_abi.sh) 另链接真实 Yak 审计对象与独立观察器，验证受测服务调用点的 16 字节对齐、32 字节影子区以及返回时八个被调方保存寄存器的恢复；三个汇编负例分别校验观察器的 E8006／E8007／E8008。该回执不代表发布工具验证任意外部对象。

[base 自举候选门禁](test_base_selfhost_candidate.sh) 使用 `bash test/gate/test_base_selfhost_candidate.sh --out-dir DIR` 在新运行目录从冻结 Seed 点火，随后用上一遍的原生编译器与扫描器成对推进 C1–C3。它核对 C2/C3 各审计根内每个单元的 `.iface`、`.ysm`、`.obj` 三件套，再比对两遍字节、FP-3 依赖摘要、原生 JSONL 及正负语料行为；失败也保留日志。原生 JSONL 经独立[诊断脚本](test_diag_native.sh)在每遍核对重复声明的引用、路径无关字节、默认输出与产物边界，再直接比较 C2/C3 的 JSONL；不等于所有引用域均已有原生用例。FP-3 先按依赖位次将 YSM 与 YKIF 配对，再按模块名映射到同一审计根的 `.iface` 并核对摘要；这是对已产出文件的核对，不覆盖编译器的 Y-7 拒绝路径。语料只取[正例](../ok/README.md)与[负例](../bad/README.md)，两遍均将 Seed 指向不存在的文件。普通用例不使用扫描器，按夹具声明的同目录依赖顺序编译；正例核对原生程序退出码与原始 stdout/stderr，普通负例核对根单元的精确诊断序列、退出码及失败后的产物边界。模块图负例用各遍原生扫描器从正式构建入口检查隔离源根，核对逐字节终端诊断和未发布边界。此语料不替代全矩阵。`--self-test` 只验证脚本与夹具，不构建；`--verify-run DIR` 复用已有 C2/C3 产物重跑完整性、字节比对、FP-3、原生 JSONL 和语料，不证明审计与当前源码对应，也不证明重新构建。两者都不能替代完整候选或正式发布。

[Win64 重定位夹具](test_coff_rel32_link.py) 可独立运行：`python -X utf8 -B test/gate/test_coff_rel32_link.py WIN64_GCC NEW_DIR`。`REL32` 用实际地址核对跨节和外部引用的有符号边界，并检查链接器拒绝越界一位。绝对重定位用实际 RVA、VA 和夹具的已知加数独立核算，由夹具拒绝 GNU ld 接受的回绕样本，并清理暂存 EXE。

[绝对重定位发布回归](test_link_absolute_relocation.py) 可用 `python -X utf8 -B test/gate/test_link_absolute_relocation.py WIN64_GCC NEW_DIR` 单独运行。正式链接入口从 COFF 检查站点宽度，只在发现绝对重定位时生成链接映射。夹具核对带空格路径的外部 `ADDR64` 和本地跨节 `ADDR32NB`，包括两个零边界、两个溢出拒绝及暂存件清理。

[YKIF 固定名称哈希审计](base_selfhost_evidence.py) 可用 `name-hashes IFACE` 独立运行，逐条复算导出、枚举成员、结构体字段和私有名的固定 FNV-1a 64。FP-3 配对同时核对 MIR 与本单元及各依赖的接口 profile。

[Win64 PE 时间戳专项](test_link_pe_timestamp.sh) 通过真实目标 GCC 正常链接一次，再显式启用非零时间戳。第二次须以 E8010 退出 1，产物发布数为 0。脚本可附带 `--native-compiler EXE` 复用原生编译器。

[Win64 运行期符号专项](test_link_runtime_symbols.sh) 可用 `bash test/gate/test_link_runtime_symbols.sh` 复跑。真实链接器生成的正常 PE 应无 COFF 符号表，并能在运行中输出静态诊断。分别修改两份暂存 PE 的真实导入名称，链接入口应以 `E7007` 或 `E7008` 退出 1，清理暂存件且无发布 EXE。

[Win64 ABI 与 x86 发射拒绝专项](test_win64_abi_rejections.sh) 在独立目录构造栈对齐、影子区、寄存器恢复、函数体 `CPUID`、栈帧与函数体等长替代编码和冗余前缀负例。默认检查终端诊断，传入 `--diag=jsonl` 检查每案唯一的结构化诊断。每次失败均核对对象、接口和 EXE 的发布边界。

[System V 目标拒绝专项](test_sysv_target_rejections.sh) 通过 `tools/link.sh --target linux-x64 --objects-only` 注入栈对齐、寄存器恢复、非法修饰名和 Win64 接口错配，核对 JSONL 与本次全部输出撤回。[syscall 拒绝专项](test_sysv_syscall_rejection.sh) 在 Linux x86-64 分别注入 `rcx`、`r11` 泄漏，用同一原生观察器核对两案 `E8016`。

[布局数量专项](test_layout_count.py) 在本机原生工具链环境中用 `python3 test/gate/test_layout_count.py --c2 C2.EXE --c3 C3.EXE --out-dir NEW_DIR` 复跑。它生成 65536／65537 字段的结构体和相同数量变体的枚举；两遍使用同一输入，禁用 Seed，按正式链接入口核对精确诊断、失败后的产物边界和成功产物的字节一致性。`NEW_DIR` 必须是父目录已存在的新路径，保留源摘要、工具摘要及逐遍原始输出。它还编译并运行[独立 ErrorSet 断言](fixtures/error_set_layout.yak)：直接构造已规范化类型表，两遍核对 65536 个成员的布局与 65537 个成员的 E5503，并逐字节比较探针的根产物。该断言不经过六位数源码声明与类型表归一化。此专项不计入常驻语料覆盖，也不替代候选或发布门禁。

[Seed 宿主拒绝专项](test_seed_host_rejections.sh) 用 `bash test/gate/test_seed_host_rejections.sh` 复跑。它直接调用冻结 Seed 的登记和外部服务入口，逐条核对 E9206–E9209、进程退出码、诊断行数，以及输出回滚和已有文件的字节。可用 `YAK_SEED_BIN` 指定待复验的 Seed。

`bash test/gate/test_base_selfhost_candidate.sh --verify-run DIR --case test/bad/E5501/fixed_array_stride_overflow.yak` 复用指定运行目录中的两份原生工具，仅核对选定负例。可以重复提供 `--case`，每次生成独立的定向回执目录。

[外部读写陷阱专项](test_c0_cross_frame_cleanup.sh) 支持 `--foreign-only`。专项检查实际 Win64 读写失败的退出状态、诊断文本与跨帧释放顺序。

[原生接口拒绝专项](test_native_iface_rejection.sh) 用 `bash test/gate/test_native_iface_rejection.sh 编译器.EXE` 复跑。正常接口返回完整三件套，四种损坏接口各只返回一条 E7012 JSONL 诊断帧，并保留逐案请求、响应和输入摘要。

[base 矩阵](t1_base_matrix.sh) 可用 `--native-compiler EXE --require-complete` 重放同一组显式编排的实配和拒绝行。此模式将 Seed 指向不存在的路径，不调用扫描器；仅由 Seed 解释的 `t1_iface_bridge` 另记为 `SKIP`，不能计入原生通过或用作发布取证。默认路径仍执行这条接口断言。

[外部 I/O 陷阱专项](test_native_foreign_trap.sh)在 Linux＋Wine 中执行 `YAK_PE_RUNNER=wine bash test/gate/test_native_foreign_trap.sh 编译器.EXE 扫描器.EXE`。它通过正式入口使用原生工具构建标准 I/O 夹具，分别检查正常回显、仅写输入句柄和仅读输出句柄，要求正常退出 0、失败退出 70 及逐字节诊断。产物摘要和原始回执保留在打印出的 `evidence` 目录。它不计入常驻负例覆盖，也不验证陷阱展开或双目标。

[陷阱清理门禁](test_trap_cleanup.sh) 和[所有权流门禁](test_owner_flow.sh) 观测 Win64 原生释放轨迹，分别验证当前帧按位点析构、槽回滚，以及正常出口、跳转和 `@push` 的所有权交接。作用域跳转覆盖内层与带标签的外层 `break`/`continue`，并与正常落尾对照真实释放顺序。默认使用冻结 Seed 路径；传入 `编译器.EXE 扫描器.EXE` 后改用原生构建，并将 Seed 路径指向不存在的文件。两种模式用同一观测器和释放断言，不证明跨帧陷阱展开。

实验性语言服务协议门禁：`bash test/gate/test_lsp_frame.sh [both|seed|win64] [frame|rpc|sync|diagnostics|candidate|definition|workspace|parity|stress]`。`frame`（默认）验证有界回显，`rpc` 验证同一开放管道上的握手、请求、错误恢复和关闭；`sync` 在真实管道上额外验证运行态全量通知经共享会话提交快照、拒绝后保持状态以及关闭和重开。`diagnostics` 将同一管道接到共享前端，核对 UTF-16 范围、版本字段协商、改正与关闭时清空，以及可信依赖不足、超分析字节上限或诊断收集截断时的明确降级。洪泛用例分别覆盖解析和名称诊断，并核对不可达分支的暂存截断不会发布被过滤的所有权错误；另外覆盖七种解析递归超限形态和七种浅语法构造的深表达式树，核对表达式树深度 64 仍可分析：超限只报告不完整并清除该版本的陈旧诊断，修正后同一会话应继续分析。另核对按值类型链深度 64 仍可分析、65 层及定长数组加深后的降级、动态数组间接递归及修正后恢复。还核对词法门禁的 2048/2049 个源码 token、1024/1025 字节名称、尾注释与 EOF 不计数，以及词法资源拒绝后的诊断恢复。Copy 分类另测共享子图估算恰为 1023 次访问仍可分析、浅层共享子图超限后降级、真正的布局错误优先及修正后恢复；不同定义的字段和枚举行交错声明，同一会话把结构体所含枚举的第二个载荷改为 owning 时，两个函数中的 Copy 判定应随版本重算，精确发布或清空错误；[定向 Seed](../../seed/test/t398_lsp_copy_lookup.yak)对拍有序和无序表的分类及估算边界。被调方 Write 槽位检查核对循环回放跨函数共享的 4096/4097 次走访边界、超限不发布先前函数的局部错误以及修正后恢复。通用所有权检查另测 64/65 次回放，以及跨函数、不可达子块共享、普通循环首遍不扣配额、超限丢弃局部错误和后续恢复。[循环前缀定向用例](../../seed/test/t401_lsp_loop_flow.yak)把单次扫描分类与旧的两次扫描逐块、逐标签对照，覆盖空块、当前和外层标签、无标签跳转、不可达后缀及前置复合语句。控制流回归在同一 URI 将两臂必返回改成一臂普通落尾，再改回，核对合流后精确的 `E6003` 范围和清空；[前端定向用例](../../seed/test/t376_lsp_frontend.yak)另逐项对照旧递归返回/落尾判定与批处理诊断元组。位置表复制另测跨函数的 4096/4097 行边界、不可达和动态短路都计费、超限丢弃局部错误以及新版本恢复。文档模式跳过析构计划和函数位置汇总；管道回归核对合法离块与返回、返回路径上的精确所有权诊断和更正后清空，前端定向用例另直接对照产物和结构化诊断。此门禁不证明前置类型检查和全部语义遍历的深度、总工作量或常驻内存预算。所有探针均不声明编辑器能力。默认使用 `python3`，可通过 `YAK_PYTHON` 指定 Python；用 `YAK_SEED_BIN` 指向从当前源码构建的候选 Seed。原生 `rpc`、`sync`、`diagnostics` 模式仅运行正式入口产生的可执行文件，不生成或验证可选审计镜像。

`definition` 只启动独立候选服务并验证同文件定义、悬停和补全：能力声明、Unicode 与 UTF-16 位置、坏参数、未打开与空位置、改版、坏文档、关闭和重开，以及同名通知静默。配套的 [Seed 绑定用例](../../seed/test/t404_lsp_definitions.yak)核对顶层、参数及局部遮蔽，并确认失败和依赖降级不保留链接。悬停另校验复合类型签名、名称半开范围、遮蔽、错误后清空，以及单条超限时仍可跳转定义。补全核对同版作用域、遮蔽和声明顺序、关键字及前缀、UTF-16 替换范围、注释和非补全位置、空候选，以及第 33 个匹配才触发截断。同模式核对完整语义记号的精确 UTF-16 五元组、空表与不可用的区别、名称错误保留本版词法结果、词法失败或记号超限不返回局部数据、恢复、关闭和不支持范围或增量请求。同模式核对文档符号的两种客户端响应、声明和名称范围，折叠的源码顺序、嵌套块和闭括号边界，以及解析失败、名称检查失败、空文档、非法 URI 和关闭。此模式不跑全候选、对拍或资源语料。

`workspace` 使用[独立授权夹具](fixtures/lsp_workspace_probe.yak)在读协议前登记真实 YKIF、可信源码目标与精确 URI。管道验证跨文件定义、未授权的近似 URI、打开依赖后诊断降级与停止跳转、遮蔽状态不变不重复发布、关闭后同版恢复及重开。该模式不修改默认候选的授权来源，也不替代原生或真实客户端验收。

真实 Neovim 门禁（Windows、Python 3.10+、官方 Neovim 0.11.5 Win64）：用同一份 `yak_lsp.exe` 执行 `python test/gate/lsp_neovim_check.py test/gate/tmp/yak-lsp-vscode/yak_lsp.exe <nvim.exe>`。参数指向解压后的官方便携包或本机安装，不安装 Neovim，也不用桌面或插件。内置 LSP 客户端直连候选 stdio，真实缓冲事件触发打开、未保存修改及关闭；明确协商 UTF-16，核对客户端实际发送非空带范围的增量修改、版本递增、协议字符列与编辑器字节列、服务回发清空、磁盘不变和正常退出。`test/gate/tmp/lsp-neovim.*` 保留 `run.json`、`editor.json`（含协议日志路径）和 `launcher.log`。与 VS Code 门禁共同补充两类客户端证据，不替代资源或发布门禁。

`parity` 以同一份原始 UTF-8 源码对拍正式批处理驱动和开放管道诊断，覆盖词法、解析、名称、类型、布局、所有权及修正成功。逐项核对驱动退出、终端精确字节及失败不写出产物，再核对 LSP 的码、严重级别、UTF-16 范围和当前版本。没有可信跨度的布局错误在 LSP 中只报告降级并清空，不猜测范围。此模式还用正式构建入口检查正例 `.obj`、`.iface`、`.ysm` 与直接驱动逐字节一致、Win64 正例可运行，并重复核对双缺失导入失败不发布。即使只选 `seed` 宿主，批处理兼容部分也需要 Win64 构建及运行环境；这些断言不验证 LSP 探针的审计镜像或原生自举固定点。

`stress` 只接受原生 Windows Python 和 Windows 可执行文件直启；不测兼容层启动器。上述门禁入口默认测探针；对正式候选用 `python test/gate/lsp_stress_check.py --candidate win64 <已有报告目录> <yak_lsp.exe>`，严格核对全量同步握手并写 `stress-win64-candidate.json`。报告的 `server_mode` 区分探针和候选，两种模式使用相同语料与阈值。用同一进程对小语料逐版核对 10 轮打开、每轮 100 次全量变更及关闭清空，每轮关闭后用标准请求确认通知处理完毕再采样。检查操作系统记录的工作集峰值不超过 128 MiB，预热三轮后关闭态私有提交量的波动不超过 2 MiB。门禁入口在输出的 `test/gate/tmp/lsp-frame.*` 目录、直启候选在显式指定的目录保留宿主、命令、可执行文件和语料摘要、已完成次数、内存采样等 JSON 数据；成功时另汇总逐次编辑往返耗时及 p50/p95。往返时间含管道传输和观察器开销，不是编辑器延迟或纯分析耗时；此门禁不证明大文档、多文件工作区或完整分析预算。

较大语料门禁（原生 Windows、Python 3.10+）：执行 `python test/gate/lsp_corpus_check.py test/gate/tmp/yak-lsp-vscode/yak_lsp.exe`。直启正式候选，在同一开放管道上用 10000 行文档核对 16384/16385 字节分析边界、末行诊断及 40 次编辑；从八个正例生成百文件，以最多 32 个同时打开的文档核对打开、诊断、修正、关闭和槽位复用。另核对单文档 4 MiB 加一字节、累计活动文本恰好 16 MiB、满额时再打开或增大一字节的拒绝，以及关闭释放额度后以同版本重试并保留准确诊断；保留满额与全部关闭后的内存采样。另起 20 个独立进程测量启动至初始化响应，不清系统文件缓存。`test/gate/tmp/lsp-corpus.*` 保留实际发送语料、`run.json`（原始语料与测量副本摘要、协议帧摘要、逐次耗时、内存采样与退出状态）。工作集峰值上限为 128 MiB；此门禁不等于完整前端预算、依赖索引、编辑器端延迟或其他宿主的发布证据。

本地字段投影用独立开放连接核对 1024/1025 步：每次二分比较和组内字段读取分别计费，只把最后一次投影移到下一字段。跨函数共享预算；预算内仍发布真实 `E5001`，超限先报告再清空，改版恢复。结构化 Seed 用例核对直接值、引用、同名异定义、首项命中、未命中、部分类型表丢弃与普通批处理不限额。

本地等值比较用独立开放连接核对 1024/1025 步：前 31 次各比较两条枚举行并读取 30 个载荷槽，末次比较一行并读取 31 或 32 个槽。`==` 与 `!=` 跨函数共享额度；限额内仍发布真实 `E5809`，超限版本连在先诊断一并清空，改版恢复。结构化 Seed 用例对照文档二分和兼容扫描的精确步数，核对字段命中、枚举载荷顺序、嵌套载荷去重、部分类型表丢弃及普通批处理不限额。

函数体作用域回归在同一开放连接重排函数的定义编号，核对跨过前序函数及嵌套块后的同名形参、精确 `E6003` 和改版清空。结构化 Seed 用例逐项对照旧作用域扫描、拒绝子块或不匹配的 DefId，并比较批处理与文档诊断。同一组回归还对照按源码序号直接读取的形参 DefId 与旧查名，核对内层同名局部不影响形参归属、相邻形参不能冒充函数、重名形参先报 `E4011` 以及改版恢复。

局部声明索引复用该开放连接，核对内外层同名绑定取不同类型和所有权状态、定义重排后内层精确 `E6003` 及改版恢复。结构化 Seed 用例覆盖 `let`、`var`、`const`、`out`，逐项对照批处理旧查名与类型侧表，另验证错误作用域或编号、重复声明无条目、预算中止后清空及批处理不分配索引。

匹配臂所有权回归验证同名载荷分属不同臂、子块同名局部退出后仍解析为载荷、定义重排后的精确 `E6003` 及改版清空。结构化 Seed 用例另核对臂体同层绑定优先、错误作用域和偏移拒绝，以及批处理与文档的完整诊断元组。

本地枚举行在同一开放连接验证不同宿主的同名变体、DefId 重排后的精确 `E2002` 与改版清空。结构化 Seed 用例逐个 DefId 对照线性查找，覆盖非连续编号、未命中、无载荷和越界、完整类型表，以及原有匹配计费。

同一连接另核对无常量、转换、下标或切片时仍完整分析，以及顶层与局部常量、仅有转换、仅有下标、仅有切片各自保留精确诊断，改回无消费者版本后清空。结构化 Seed 用例对照快照需求、批处理完整诊断元组和原有整数试算边界。

## 覆盖

- 确定性：相同输入两次构建产出逐字节一致
- 收敛：三遍自举产出的可比性（`../../spec/proc/fixpoint.md`）
- 资源预算：输入、步数、内存、递归深度上限
- 清理：`../tmp/` 在构建后可完全清理

## 约定

- 门禁判定失败一律视为失败，不设"宽限值"。
- 每类门禁对应 `../../spec/proc/gate.md` 的定义。
- 未实现的能力按"缺口"如实计数，不写成通过；缺口关闭后脚本会提示改成实配断言。
- 取证只记录实际执行结果；取不到就失败，不按推断补写。
