# register

## 元信息

- 名称：register（寄存器分配）
- 级别：full
- 状态：草案
- 依赖：`x86.md`、`abi-win.md`、`abi-linux.md`、`emitter.md`、`select.md`、`../ir/mir.md`、`../lang/asm.md`

## 一、范围

1.1 本文规定 full 层将虚拟局部（`LocalId`）映射到目标物理寄存器与栈溢出槽的确定性分配契约。

1.2 base 期 `yakc-min` 采用 `x86.md` 1.2 栈槽直译模型，不执行寄存器分配；本规格只在 full 层激活。

## 二、寄存器分类与约束

2.1 目标物理寄存器划分为四个互不相交的集合（由各目标架构文档给出具体名表，如 `x86.md` 二）：
- **通用整数寄存器（GPR）**：承载标量整数、`bool`、`char`、`&T`、裸指针与 `&function`；
- **浮点 / 向量寄存器（FPR / VEC）**：承载 `f32`、`f64` 与便携 SIMD 向量；
- **调用约定分类**：按目标 ABI（`abi-win.md` / `abi-linux.md`）划分为 caller-saved 与 callee-saved；
- **保留寄存器**：栈指针（如 `rsp`）、帧指针（如 `rbp`）及架构专用指针（如 `rip`），永不分配给普通虚拟局部（RG-1）。

2.2 **不可放寄存器的聚合与取址局部**：需要内存地址的 `place`（发生 `borrow_*`、`field_addr`、`index_addr`）、`out` 槽位以及超过单寄存器宽度的聚合对象固定分配在对齐的栈帧槽位，不参与寄存器提升（除非优化遍先完成标量替换）。

## 三、活跃性与清理边保全

3.1 活跃性分析按 CFG 逆后序迭代至唯一最小固定点，必须同时覆盖正常控制流边与 `../ir/mir.md` 4.13 的位置专属陷阱清理边。

3.2 在任何可陷阱指令或 `invoke_*` 调用点，其私有清理块所引用待析构局部的活跃区间必须延伸至清理块内对应 `drop` 指令；分配器不得提前覆盖该溢出槽或寄存器（RG-2）。

## 四、调用点与内联汇编约束

4.1 **函数调用点**：跨越 `call_*` / `invoke_*` / `call_foreign` 活跃的值必须分配至 callee-saved 寄存器，或在调用前确定性溢出至栈槽、调用后恢复；被调函数入口/出口须成对保存并恢复实际使用过的 callee-saved 寄存器（RG-3）。

4.2 **内联汇编约束**：`@asm` 显式指定的物理寄存器绑定与 `clobber(...)` 集合（`../lang/asm.md` 三）作为硬约束输入分配器；被 clobber 的寄存器在 `@asm` 点不得承载跨点活跃虚拟值（RG-3）。

## 五、确定性分配与溢出布局

5.1 活跃区间排序、冲突图遍历与溢出候选选择必须仅依赖 `BlockId`、指令序号与 `LocalId` 的确定顺序；同优先级打破平局的规则固定（取最小 `LocalId`），禁止依赖哈希遍历或地址（RG-4）。

5.2 溢出槽按首次分配顺序在当前函数栈帧中布局，每个槽位满足其类型自然对齐（`../lang/layout.md`），函数总帧长向上对齐至目标 ABI 要求（x86_64 为 16 字节）。

## 六、拒绝形态

| 编号 | 条件 |
|:---|:---|
| RG-1 | 将保留寄存器或类型类别不匹配的寄存器分配给虚拟局部 |
| RG-2 | 溢出槽违反对齐要求、发生活跃区间重叠，或破坏陷阱清理边上的待析构值 |
| RG-3 | 未遵守目标 ABI 的 caller-saved / callee-saved 契约或 `@asm` 物理约束/clobber |
| RG-4 | 寄存器或溢出槽分配依赖非确定性顺序导致输出漂移 |
