# spec

## 职责

全部契约的**唯一住所**：语言、中间表示、目标后端、流程门禁。任何契约不得在规格区之外成文。

## 结构

- `index.md` —— 全局注册表：规格状态（`proc/status.md`）× 编译器（min / full）实现态矩阵
- `audit.json` —— `python tools/audit_spec.py --report` 生成的结构检查、直接依赖及待冻结条目快照；不授予语义确认
- `tpl/` —— 规格写作模板
- `lang/` —— 语言规格：Yak 是什么（实现无关）
- `ir/` —— 中间表示：MIR 与 YSM
- `target/` —— 目标与后端：ABI、对象格式、发射器、优化
- `proc/` —— 流程与门禁：构建、门禁、点火、收敛、诊断、错误码

## 边界

- 与 `compiler/`：本目录规定"应当如何"，`compiler/` 实现"如何做到"。
- 与 `test/`：本目录规定规则，`test/` 提供验证规则的正负例。
- 与根 `README.md`：那里描述项目整体结构，本目录及其下 `README.md` 描述局部。

## 写作约定

- 手册式：只做规定，不写解释。
- 每份文档首部带级别与状态字段；状态取值与实现权限见 `proc/status.md`，契约态实现只依赖已确认规格，参考态实现只依赖草案-可实施规格。
