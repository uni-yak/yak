# lsp

## 元信息

- 名称：lsp（独立 Yak 语言服务）
- 级别：流程
- 状态：草案
- 依赖：`../lang/base.md`、`../lang/foreign.md`、`diag.md`、`gate.md`

## 一、边界

独立的 stdio 服务消费共享前端的结构化诊断。批处理的单向输出由 [诊断规格](diag.md) 规定。本文覆盖独立候选服务、共用检查和定向探针；独立服务对客户端声明的能力及与探针的差异见第九节。协议拒绝使用 JSON-RPC 错误码。

## 二、stdio 帧（候选）

- 头使用 ASCII，每行以 CRLF 结束，空行终结头；包含终结空行在内最多 8192 字节。字段名非空，仅接受 ASCII 字母、数字和连字符，名称后紧接冒号。值只接受可打印 ASCII 和 HTAB。未知字段不改变分帧；上层仍须验证正文为 UTF-8 JSON。
- 必须且只能有一项 `Content-Length`，字段名按 ASCII 不区分大小写比较。长度值允许两端 SP / HTAB；中间只允许至少一个十进制数字（允许前导零），范围为 0 至 33554432，累加前检查上限。计量单位是字节，不能按字符计算。零长帧有可信边界，但不是有效 JSON。
- 一次只读一个头字节；通过头校验后，正文读取请求不超过本帧剩余字节，短读累加，返回零则截断。这样在头和正文已经收齐时不必等待下一帧或 EOF。阻塞 I/O 不承诺对迟迟不发送剩余字节的对端超时。
- 尚未读取头时的 EOF 与头内截断区分；头超限或不合法时不得尝试重新同步或把后续字节解释为正文。截断、分配失败或运行时 I/O 陷阱终止会话；运行时陷阱可写 stderr，不向 stdout 写普通文本。可信帧边界内的 JSON 错误由后续 JSON-RPC 层处理，不改变下一帧的读取边界。
- 写出时用 `Content-Length: <十进制字节数>\r\n\r\n`，紧接正文，不附加换行。不写超限正文，也不写其头。

## 三、有界 JSON（候选）

- 每帧解析恰好一个 UTF-8 JSON 值，允许 JSON 空白，拒绝多余正文、注释、尾逗号、非法数值、裸控制字符、非法 UTF-8、无配对代理项及非法转义。数值保留原文，不经浮点或有损整数转换。
- 解析使用前序节点表，保留原始字节半开区间；不复制整个正文或预先解码任意字符串。深度最多 32 层容器，节点最多 65536 项（对象键另计一项）。超限在添加容器或节点前拒绝，与普通语法失败区分；分配失败仍传播，不当成成功或普通 JSON 错误。
- 对象字段以解码后的键比较，对同一个受消费的键区分缺失、唯一和重复（包括不同转义拼写）。解释协议封包的调用方不得用首值或末值掩盖重复。字符串提取按调用方的解码字节预算，超限不返回部分文本。

## 四、JSON-RPC 封包与生命周期（候选）

- 只消费单个 JSON 对象，不处理批次。语法错误返回 `-32700`；超出 JSON 解析预算、非对象和坏封包返回 `-32600`，此时响应 id 为 `null`。`jsonrpc` 必须唯一且解码为 `"2.0"`，`method` 必须唯一且为非空字符串。对消费的 `id`、`params` 也拒绝重复。方法名按解码值区分大小写；未消费的扩展字段不改变路由。
- 无 `id` 的有效方法封包为通知，不返回结果或错误；有 `id` 的请求仅接受字符串或范围为 `[-2147483648, 2147483647]` 的十进制整数字面量；数值不接受小数或指数写法。原始 id 表示最多 4096 字节（包含字符串引号），超限、显式 `null` 或其他类型均视为坏封包。有效请求的响应复用原始 id 字节，不重新转义或数字化。服务尚不发起请求；无方法且包含 `result` 或 `error` 的对象按意外响应丢弃，不回送错误串。
- 等待 `initialize` 时，只有该方法的请求可开始初始化，其 `params` 必须为对象；其他请求返回 `-32002`。应用接受初始化后等待 `initialized` 通知，该通知接受省略、`null` 或空对象参数；等待期间一般请求仍返回 `-32002`。重复的 `initialize` 请求始终返回 `-32600`。路由仅给出建议的下一状态；初始化和关闭只有在成功处理后才提交。
- 运行中 `shutdown` 仅为不带参数的请求（兼容显式 `null`），参数不匹配返回 `-32602`，成功后返回 `null` 并进入已关闭状态。其余未注册请求返回 `-32601`。已关闭状态的请求返回 `-32600`。`exit` 仅为省略参数或显式 `null` 的通知，可在各状态退出；已关闭时退出码为 0，否则为 1。未处理通知不改变状态。协议、全量同步和诊断探针初始化时返回空的 `capabilities`；独立候选服务按第九节声明能力。

- stdio 协议探针和候选服务在成功写出响应后才提交相应状态；无需响应的有效通知可直接提交状态。只有收到关闭后的 `exit` 通知才正常退出（0）；未收到 `exit` 就遇到帧间 EOF 时退出 1，坏头或正文截断退出 2，不写响应也不重新同步。可信帧内的语法错误（包括零长正文）返回解析错误，保持会话状态并继续读下一帧。宿主 I/O 陷阱不被重解释为协议退出。

## 五、内存文档分析（候选）

- 文档前端接收当前 UTF-8 源码的只读字节切片和调用方文件编号，每次分析独立创建诊断缓冲。按严格编译顺序执行词法、解析（保留静态池）和 base 校验；不替编辑器文本补写末尾 LF 或改写换行。任一阶段拒绝后不继续分析，保留该阶段的结构化诊断。
- 上述阶段通过后，若 AST 含导入而未提供可信的依赖上下文，返回「缺少依赖」，不执行名称、类型、布局和所有权检查，不制造未找到模块的诊断。无导入则继续运行这四个阶段，错误阶段结束后先停查；仅全部通过才能返回「检查通过」。诊断沿用编译器的排序、严重级别、错误码及原始跨度。分配失败传播，既不冒充源码诊断，也不返回「检查通过」。
- 本入口不读写宿主、不终止进程，不检查根入口、不构造或写出编译产物，也不改变批处理或既有内存编译入口的诊断行为。文档模式分别限制解析器原始诊断和后续阶段共享缓冲的收集量，各最多 64 条；词法仍在首错时停止。达到上限后只在后续条目实际被舍弃时标记截断，不再为这些条目分配空间。解析先截断，再按既有规则排序和去重；保留的诊断仍按原有规则处理。所有权不可达分支的临时收集使用同一单缓冲上限，仍过滤仅依赖可达状态的诊断；临时截断向上传播，但不推定被舍弃条目的严重级别。遇到收集截断返回「诊断收集不完整」，既不造错误码也不认为检查通过。解析深度、分析工作量与其余资源上限仍须另行验证。

### 可信依赖材料（纯宿主入口）

- 只接收宿主授权登记的当前模块名、直接依赖下标、YKIF 字节及独立的预期模块名和摘要。每批最多 32 份接口、32 个直接下标及 32 个打开模块登记；单个模块名最多 1024 字节，材料及登记字节合计最多 32768。复用接口解码、摘要、布局及可见性校验，沿直接依赖验证闭包的模块名和摘要。登记无效、损坏、缺失、过时、遇环、被打开缓冲遮蔽或超配额时不交付部分依赖。传递名义类型仅用于检查，不自动成为源码可见的直接导入。
- 打开模块身份由宿主登记，不从 URI 或文件路径推导。已打开的直接或传递依赖遮蔽旧二进制接口；在尚不能从打开缓冲构造可信接口时，消费者降级，不能回退到被遮蔽的接口。无关打开模块不阻断分析；关闭后可重新验证已授权材料。材料状态与当前缓冲的诊断独立，失败时仍执行当前版无材料前端，不沿用旧语义索引。
- 宿主可对某张当前文档票据刷新分析。身份由当前模块、profile、前端版本、材料状态和规范排序的已验证根接口摘要构成；根接口的摘要绑定传递依赖记录。身份与已提交版本不变时复用分析，不使用路径或 mtime 识别内容。身份变化时先使同版旧票据失效，并清除旧索引，再计算本版结果。新正文和关闭重开仍分别以文档版本和打开代区分；诊断由宿主按返回的新票据发布。
- 宿主也可提交完整的批量登记，最多 32 项。每项以文档槽位和打开代绑定模块身份，仅使用该消费者获授权的材料及直接下标，不跨登记借用材料。失效打开代不参与遮蔽；同一打开项或模块重复登记时拒绝整批。有效登记形成打开模块集合，再按 URI 字节序返回各文档的新分析或复用状态；撤销登记时清除原可信索引并转为无材料分析。
- 完整检查成功时，文档索引可保存直接导入的普通导出引用：仅记录实际绑定的路径末段半开区间，按源码偏移排列，以模块名、已验证的接口摘要及该接口内的导出编号标识目标。快照内重复引用共享接口身份；导入前缀、字段和枚举变体不提供这类索引。未完成分析或上下文失效不沿用旧引用。接口身份本身不是源码位置。
- 在有可信构建登记时，宿主可独立验证一份目标源码。登记必须把目标 URI、模块名、源码 SHA-256 和 YKIF 摘要绑定为同一构建产物；不能给任意候选现场计算摘要后当作授权。入口校验原始源码字节、接口和 URI，仅把完整解析的公开函数、枚举及结构体逐一对应到接口的名称、类别和导出编号。缺项、重复、无法映射或超预算时不给出部分索引。索引只保存已验证身份、URI、公开声明名及类别和精确的 UTF-16 声明名范围，按模块、接口摘要及导出编号精确查询；不保存源码或接口正文。
- 配置宿主可为每次会话分发提供当前授权的目标集合，最多 32 项；未传入、撤销或超额时仍可查询同文件定义。当前消费者必须已经提交同代分析，同文件绑定优先；导入查询只有唯一的模块名与接口摘要匹配、对应导出编号有位置、URI 不与另一有效目标冲突且未被打开缓冲遮蔽时，才返回该目标的 `Location`。范围按声明名的 UTF-16 坐标编码。找不到、歧义、目标失效或消费者尚未提交本版索引时返回 `null`；参数错误仍返回 `Invalid params`。
- 可选 stdio 嵌入入口在读第一帧前接收宿主授权的只读登记，最多 32 个 URI／模块配对，URI 或模块名重复无效。有效的目标位置必须有对应的登记，且 URI 和模块名均完全匹配。文档打开、变更或关闭后，以解码后的原样 URI 匹配登记，按当前打开代绑定；不解析路径或百分号，不接受初始化参数作为授权。相关打开项集合变化时重验消费者，关闭项的清空先于剩余文档按 URI 字节序发布；已提交的相同版本及分析身份不重复发布。未登记文档仍走无材料前端。
- 纯工作区符号查询仅覆盖宿主提供的可信目标，不枚举私有声明、未登记的文件或打开缓冲中的声明。按 URI 字节序和源码声明偏移稳定返回，以 ASCII 不区分大小写匹配 UTF-8 标量子序列，空查询匹配全部。最多接收 32 个目标及 256 字节的查询，最多返回 512 项；非法查询、重复模块或 URI、超预算不返回部分列表。打开的同 URI 缓冲遮蔽磁盘结果；查询结果分别报告可用及遮蔽的可信目标数，不承诺全工作区覆盖。该入口尚不对协议声明能力。
- 纯宿主入口只消费宿主已经授权登记的材料，不读取文件。可信源码位置须绑定已验证接口和源码的身份。第九节的独立工作区索引从协议接收文本快照，按该节提供查询；文本快照本身不构成对 YKIF 或可信源码位置的授权。

## 六、文档位置（候选）

- 位置索引只配合同一版 UTF-8 文本使用；调用方必须连同该版文本保存，不以相同字节长度代替版本匹配。索引不复制、不规范化文本。单文档文本最多 4194304 字节，最多 65536 行（尾换行后的空行计入）；超限或非法 UTF-8 不提供部分索引，分配失败仍传播。
- 行列均从零开始。默认按 UTF-16 码元计列，非 BMP 标量占两列；协商 UTF-8 时按字节计列，协商 UTF-32 时按 Unicode 标量计列。LF、CRLF、裸 CR 均是位置层的行分隔符。行尾对应分隔符起点，分隔符之后是下一行第零列。拒绝落在 CRLF 或 UTF-8 标量内部的字节偏移。空文本包含第零行，尾分隔符之后有一空行。
- 反向定位拒绝不存在的行和落在编码标量中间的列；超出有效行长度的列归到行尾。增量变更使用同一位置映射，映射后起点不得晚于终点。半开范围先核验文件归属，再验证起点、长度及两端边界，保留合法零宽范围。调用方发布前核对文件归属、打开代、文档版本和依赖代。
- 每行存储边界及当前编码的列长度。长行按字节间隔在标量边界建立检查点（阈值 256 字节）。查询对行和检查点二分，单次局部扫描不超过 259 字节。

## 七、文档同步与查询（候选）

- 只在运行态接收 `textDocument/didOpen`、`textDocument/didChange`、`textDocument/didClose` 通知。消费字段在所属对象中须唯一且类型匹配。打开需要 `languageId` 为 `yak`、URI、版本和文本，关闭只需要 URI。变更需要版本及非空的 `contentChanges`。版本使用有符号 32 位整数字面量，未知扩展字段忽略。
- 全量探针只接受一个包含字符串 `text` 的元素，须省略 `range` 与 `rangeLength`。独立服务可按顺序应用最多 256 个全量替换或增量补丁。全量元素同样须省略两个范围字段；增量元素的 `range` 按协商编码解析到前一项应用后的文本。`rangeLength` 如存在，须为非负的 32 位整数，切片边界由 `range` 决定。任一项无效或超限均放弃整次变更。全部成功后一次提交文本、索引和版本。
- URI 是解码后的不透明标识，最多 4096 字节；须有字母开头且仅含字母、数字、加号、点号、连字符的非空 scheme，冒号后非空，不接受裸控制字符、ASCII 空格或不完整的百分号转义。不做路径解析、百分号解码、大小写折叠或宿主访问。JSON 的不同转义拼写解码为相同字节即是同一标识，URI 中的百分号拼写则按原值比较。
- 同时最多打开 32 份，活动文本字节总量最多 16777216；每份同时受位置索引的文本与行数上限约束。重复打开、未打开变更或关闭、相同或倒退版本、超预算或无效输入均保持现有文档状态，分配失败传播。活动额度按提交后的文档文本计算；处理中可能同时持有旧快照与工作副本，JSON 帧和服务资源分别受自己的门禁约束。
- 每次成功打开分配会话内非零且不回绕的打开代；关闭立即释放文本、索引与活动额度。快照核对至少包含槽位、打开代与版本，槽位可复用但旧票据不会复活。关闭事件提供清空所需的 URI；后续依赖分析接入时另核对适用的依赖代。存储不自行发布诊断；受理结果和失败原因由服务层消费。
- 共享 stdio 会话仅将运行态、无 `id` 且 `params` 为对象的这三种通知交给存储。同名请求按未注册请求处理，不触碰文档。会话将已提交的快照票据或关闭事件交给调用方，再由调用方决定诊断分析和发布；同步探针不发布诊断，也不宣告同步能力。

### 同文件定义与悬停（候选）

- 仅候选服务在运行态处理 `textDocument/definition` 和 `textDocument/hover` 请求；无 id 的同名通知不修改状态、不回复。参数须含唯一的 `textDocument.uri` 与 `position.line`、`position.character`；行列为非负的 32 位整数字面量，URI 沿用同步校验。非法参数返回 `-32602`；合法位置未命中返回 `null`。
- 只在同版无错误、未截断且完整的严格前端结果上，从已解析的真实绑定提取同文件名称位置。首版覆盖可核验的顶层实体、形参及局部绑定引用，不猜测字段、变体、导入或其他未对接形态，也不把声明 token 本身当作使用点。链接以引用 token 的半开字节区间为键，只保留不冲突的使用和目标跨度。快照不保留 AST、名称池或定义、类型编号。
- 打开或变更先替换为无索引的新快照，诊断发布成功且槽位、打开代、版本仍匹配后才提交链接，关闭立即释放数据。未打开、错误或降级快照、空白、无绑定及不可映射位置返回 `null`。命中返回一个同 URI 的 `Location`，范围是目标名称，按同版索引和会话编码换算。同文件查询无命中时，独立服务可按第九节查询其工作区索引。
- 悬停使用同一次严格检查的绑定类型与函数签名，覆盖可识别的声明名称和引用；返回 `plaintext` 内容及命中名称按会话编码计算的半开范围。不显示未知类型，不使用旧版本或源码拼接猜测类型。同一声明的悬停文本共享存储，每条最多 512 字节，类型展开深度最多 16，每文档文本总量最多 16384 字节；超限省略整个条目，不影响定义或诊断。

### 基础补全（候选）

- 独立服务按第九节声明触发字符。运行态 `textDocument/completion` 沿用上节的 URI、位置、通知和无效参数约定。基础补全使用已提交的当前版语义；成员和工作区补全走第九节的扩展入口。
- 基础补全从词法表和同版作用域区间提供关键字及可核验的同文件名称，选取最内层真实绑定，尚未可用的内层声明不回退到被遮蔽的外层项。注释和字面量内部不提供基础补全。
- 按光标前缀过滤，按候选拼写的 UTF-8 字节序返回最多 32 项；多于 32 个匹配才设置 `isIncomplete`。受支持的位置没有匹配时返回空列表。每条补全替换光标所在的完整名称区间，无名称时在光标处插入；编辑范围按同版文本与会话编码换算。

### 完整语义记号（候选）

- 仅候选服务声明 `semanticTokensProvider`，图例依次为 `keyword`、`string`、`number`、`operator`，无修饰符。只处理运行态 `textDocument/semanticTokens/full`，不声明范围、增量或结果 ID；无 id 通知静默。请求使用与其他查询相同的 URI 校验，非法参数返回 `-32602`。
- 从同版扫描器已确认的词法跨度提取：关键字、布尔值和内建记号归入 `keyword`，字符串与字符归入 `string`，整数归入 `number`，扫描器的运算符及标点归入 `operator`。不猜普通名称类别，不另扫描注释。每个记号必须可映射为非空、单行、不重叠的会话编码范围；按源码顺序输出标准五元组，相对列以同一行上一记号起点为基准，换行后以零为基准。
- 词法成功即有本版记号，后续解析或检查失败不影响它；无着色记号返回 `{"data":[]}`。未打开、关闭、未分析、词法失败、超出词法配额或不能可靠转换范围时返回 `null`，不发布部分或旧版记号。记号受现有 16384 分析字节、2048 源码记号等词法上限约束。

### 文档符号与折叠（候选）

- 仅候选服务声明 `documentSymbolProvider` 和 `foldingRangeProvider`。两种请求只接受已验证的文档 URI，无 id 通知静默，非法参数返回 `-32602`。解析成功且结构预算内时，从同版 AST 提取；后续检查失败不影响本版结构。关闭、词法或解析失败、解析深度超限或无法转换跨度时返回 `null`；已分析但无条目时返回空数组。
- 文档符号按源码顺序包含有可信名称记号的顶层函数（含 foreign）、常量、结构体与枚举，不展开成员或局部，也不把导入当声明。明确支持层级符号的客户端收到声明完整范围和名称选择范围；其余客户端收到含当前 URI 及名称范围的扁平符号。坐标均按会话编码换算。
- 折叠只从解析器确认的结构体、枚举和语句块中提取成对花括号，按起点源码顺序输出按行范围，结束行保留实际闭括号；不能形成折叠的单行或相邻行区间省略。注释、字面量中的括号，以及未确认的结构均不推断。

## 八、诊断推送（候选）

- 仅处理共享会话已提交的打开、变更、关闭事件；同一线程按通知顺序分析与发送。打开或变更以槽位、打开代、版本核对快照，使用同版文本和索引；编码完成后再次核对票据。关闭立即清空该 URI 的诊断，不携带关闭前版本。拒绝或过期的通知不发布新诊断，也不清除仍有效的旧诊断。
- 仅在初始化参数 `capabilities.textDocument.publishDiagnostics.versionSupport` 各级字段唯一且最终值是 JSON 布尔 `true` 时，打开与变更的 `publishDiagnostics` 包含当前版本；否则省略。诊断版本字段与同步模式分别协商。
- 沿用编译器顺序、错误码、严重级别；`source` 为 `yak`。没有通用消息表时显示阶段和错误码，不重构终端文案。只检查已排序结果的前 64 条，最多发布 16 条；拒绝其他单元或文件、未知严重级别、饱和长度或不可映射的跨度。不补造位置；真正的零宽范围保留。
- 候选接线对每次分析另设 16384 字节上限，不等同于文档存储额度或完整分析预算。缺少可信依赖、超分析字节上限或诊断裁剪时，先用标准 `window/logMessage` 标明原因，再发送该 URI 当前版的可用诊断（没有可用诊断则为空）；空列表只替换陈旧诊断，不表示前端完整通过。存储预算拒绝只记录状态、保留旧快照和诊断。状态消息不带绝对 URI 或源码；分配与输出失败终止会话。若前端诊断收集截断，优先报告该原因，再发布当前版本保留下来的可定位诊断；收集、编码扫描和发布的上限互不替代。

- 文档词法扫描最多接受 2048 个源码 token；空白、注释和 EOF 不计入。扫描在超配额的下一项分派前停止，不为该项分配 token 或驻留名称；真实的源字节编码、尾换行及已扫描注释错误仍沿用词法规则。普通名称及 `#`、`@` 项最多 1024 个 ASCII 名称字节，前缀不计；在名称查表或驻留前检查。任一超限均丢弃残缺 token 流，不进入解析，先报告分析不完整，再清空当前版本诊断，不新增编译错误码。批处理不启用这两条配额；它们不限制总语义工作量或进程内存。

- 文档词法名称驻留另设 12288 步，同一文档内普通名称与合法的 `#` 名称共享；关键字、通配符和内建项不入驻留表。查找、插入及重新插入每次访问槽前扣一步，包含终止的空槽；哈希与长度相等时，在原始字节复核前按名称长度整批预扣。初始分配和扩容前按新桶初始化数与旧桶巡检数整批预扣；迁移及当前插入完整后才提交新表。恰好用完仍可完成；下一次预扣不足即停止，丢弃本版残缺词法结果，不进入解析，先报告不完整再清空当前版本诊断。新版本重新计费，批处理及正式驱动不限额。名称哈希计算、源码扫描、其他阶段名称查找及前端总工作量不计入。
- 文档前端的解析器共享 64 个活动递归入口配额，覆盖块、表达式、常量表达式、前缀/后缀表达式、引用与一般类型解析，以及嵌套类型校验。超限后停止读 token，不发布本次残缺解析的任何诊断，不进入语义阶段；先记录不完整状态，再发当前版本的空诊断。批处理的原解析入口不启用此配额。这个配额与表达式树深度独立。
- 干净解析完成后、base 与语义阶段开始前，文档前端按后序表达式池检查最长父子链，叶算一层，最多 64 层。循环构造的二元和后缀链也计入；普通和移动实参计入，`out` 实参是名字而非表达式边。每个节点及其表达式边至多访问一次，暂存每节点一个深度，不递归。超限或异常表达式边拒绝进入后续阶段；先发送不完整状态，再清空当前版诊断，不合成编译错误。批处理不启用此检查；它也不限制类型图、全部语义遍历、整体工作量或内存。

- 本地类型检查无错误后、布局与所有权阶段前，文档前端检查按值类型链，叶算一层，最多 64 层。定长数组、可空类型、成功值与错误集合、局部结构体字段和枚举载荷均可产生按值边；引用、切片、函数引用及动态数组头不沿被引用类型递归。检查限制活动遍历深度，复用已计算的后缀高度；遇到已活动的节点不再沿该边递归，短按值环仍由布局按原规则拒绝。超限时记录分析不完整并清空当前版诊断，不合成错误码。批处理不使用该门禁；它不限制前置类型检查、其余语义递归或总工作量。

- 文档匹配模式的解析判重另设 1024 步，跨匹配、嵌套块与函数共享。对一个非通配模式，每次读取已见候选行前扣一步；仅路径等长时逐段比较，每次读取对应分段对前再扣一步。遇到首个不同分段或首个相同路径即结束相应比较；通配模式本身的顺序检查不计步。恰好用完仍可完成；下一步付不起即停止本次解析，丢弃局部诊断，不将残缺 AST 交给后续阶段，先报告分析不完整再清空当前版本。新版本重新计费，普通批处理及正式编译驱动不限额。模式构造、错误恢复、类型检查及前端总工作量不计入。

- 文档显式解析错误恢复另设 1024 个跳过 token，跨文件项、语句、匹配臂、枚举与结构体成员同步、拒绝的泛型形态和旧式 `move` 形参共享。每次跳过非 EOF token 前扣一步，恢复时消费的逗号、分号和泛型闭合 token 也计步；正常语法推进、按语法解析被拒绝的成员、停在同步点时的只读前瞻、解析总工作量不计入。恰好用完仍保留真实诊断；下一步付不起即停止解析，丢弃部分诊断和截断标志，不接入静态池或进入语义阶段，先报告分析不完整再清空当前版本。新版本重新计费，普通批处理及正式编译驱动不限额。

- 文档 `out` 实参类型检查另设 1000 步，跨参数、调用和函数共享。形参确认为可写引用后，在按节点种类、调用编号、实参序号排序的引用表中二分定位。每读取一个候选前扣一步，命中立即停止，未命中按实际读取的行数计费。恰好用完仍可完成；下一步付不起时停止函数体类型检查，丢弃部分类型表和诊断，不进入常量检查，先报告分析不完整再清空当前版本。新版本重新计费，普通批处理及正式编译驱动不限额。形参类型查询、名称解析、所有权检查及前端总工作量不计入此项。

- 文档类型检查在名称解析完整通过后，按本次分析的定义数建立函数签名侧表。索引按定义编号直接定位签名；非函数和非外部函数定义不占用签名行，零编号、缺失或越界均不命中。函数体类型检查与所有权检查复用同一侧表；改版重建，不继承旧版本结果。普通批处理和正式编译驱动不分配此侧表，仍使用原始签名表。此项不新增降级状态，也不代替前端总工作量或资源限制。

- 文档本地字段投影另设 1024 步预算，跨表达式和函数共享。每次投影按 DefId 二分定位字段组的半开区间，再按声明顺序查该组的字段名，首项命中即停止。二分比较和组内候选读取各在访问前扣一步；组外字段只可能在二分比较中访问。直接值和引用指向的本地类型共用预算。恰好用完仍可完成；下一步付不起时停止该次查找，放弃部分类型表与诊断，不进入常量检查，先报告分析不完整再清空当前版本。新版本重新计费，普通批处理及正式编译驱动沿用原查找且不限额。构造器、导入字段、所有权检查和前端总工作量不计入。

- 文档本地等值比较另设 1024 步预算，`==` 与 `!=` 跨表达式和函数共享。按 DefId 二分查本地字段是否存在与唯一枚举行；二分比较、枚举载荷槽和去重队列候选都在读取前扣一步。按原语义在第一个已知不可比较载荷处停止；重复载荷不重复扩展。恰好用完仍可完成并保留真实诊断；下一步付不起则停止函数体类型检查，丢弃部分类型表与诊断，不进入常量求值，先报告分析不完整再清空当前版本。新版本重新计费，普通批处理和正式编译驱动不限额。导入类型、布局、所有权检查及前端总工作量不计入。

- 函数形参类型和所有权检查共用名称解析已建立的函数体块到作用域映射，不按每个函数扫描完整作用域表，也不增加索引或额度。查找要求作用域非零、编号有效、为函数作用域且归属当前 DefId；嵌套块不满足该约束。普通批处理与文档前端共用该查找，诊断及停止规则不变。

- 名称解析通过后，文档类型检查和所有权检查按形参的源码序号读取函数定义之后连续预留的 DefId。候选须属于当前函数作用域，且种类为形参、名称吻合；不新增侧表，也不逐形参按名搜索。重名形参仍在名称阶段拒绝。普通批处理与正式驱动仍按原作用域查名；类型、所有权诊断及既有配额不变。此项不覆盖局部声明、模式绑定或前端总工作量。

- 文档名称解析预留 `let`、`var`、`const` 和 `out` 声明时，将成功绑定的 DefId 写入当前 AST 的局部声明下标表；跳过重复声明，预留超限清空部分表。每个槽位为一个 `u32`，表长不超过当前文档的局部声明 AST 池长度，由现有记号上限约束。类型检查与所有权检查在名称阶段成功后直查，核对作用域、名称、种类和声明偏移，不向外层查名。表只存于当前分析，不跨版本保留，不用于普通批处理或正式驱动，不覆盖模式绑定和前端总工作量。

- 名称解析成功后，文档所有权检查沿用已解析的 `out` 槽位 DefId。每次检查调用时只在首个 `out` 实参二分定位该调用的首行，之后核对节点种类、调用编号和实参序号并顺次读取；普通实参不推进引用游标。不新增索引或名称查找，普通批处理及正式编译驱动仍按作用域查名。借出、直接错误传播、诊断及原有配额不变；此项不限制所有权状态表或前端总工作量。

## 九、独立候选入口

- 在 MSYS2 UCRT64，继续用 `bash compiler/lsp/build.sh <仓库内输出目录>` 通过正式编译入口构建 Win64 `yak_lsp.exe`；该单参数入口的目标不随宿主变化。独立 Linux 入口见本节下方。候选服务与诊断探针共用进程内分析与分帧循环，不启动编译子进程，不写临时源码；支持以下完整 IDE 协议能力：
  - **位置编码协商（`positionEncoding`）**：解析 `initialize.params.capabilities.general.positionEncodings`，按客户端偏好在 `utf-8`、`utf-16`、`utf-32` 中协商并在 `capabilities.positionEncoding` 声明结果；未声明时默认 `utf-16`。所有诊断、跳转、悬停、补全、符号、折叠、格式化、重命名与 Code Action 均统一使用协商编码。
  - **文档同步与取消（`textDocumentSync.change: 2`、`$/cancelRequest`）**：支持顺序增量补丁（含 `range`）与全量替换（不含 `range`）；识别 `$/cancelRequest` 通知并对已取消请求返回 `-32800`（`Request cancelled`）。
  - **工作区索引与工作区符号（`workspaceSymbolProvider: true`）**：默认候选入口解析 `initialize.params.rootUri` / `workspaceFolders` 与 `initializationOptions.workspaceFiles` 及 `yak/workspaceFiles` 增量同步通知（由宿主/VS Code 扩展自动扫描工作区 `.yak` 文件并推送），按根 URI 自动推导 Yak 模块名并维护跨文件导出表。`workspace/symbol` 联合检索已打开文档（实时缓冲优先）与未打开工作区文件；嵌入宿主 `configured_service` 仍保留原可信内存目标模式。
  - **成员与工作区补全（`completionProvider.triggerCharacters: [".", ":"]`）**：支持 `.` 触发结构体字段补全，`::` 触发枚举变体与工作区模块导出项补全。普通位置合并跨文件模块与导出候选；补全可处理刚输入 `.` 或 `::` 的不完整缓冲。
  - **确定性格式化（`documentFormattingProvider: true`）**：`textDocument/formatting` 在 64 KiB 有界预算内执行规范化（LF 行尾、按花括号缩进、清理行尾空白、折叠多余空行、保证末尾单 LF），无改动时返回空数组 `[]`，不破坏字符串与注释内容。
  - **安全同文件重命名（`renameProvider: { prepareProvider: true }`）**：`textDocument/prepareRename` 校验光标命中绑定声明或引用并返回范围与占位符；`textDocument/rename` 校验新名称符合 Yak base 标识符规则（拒绝关键字、保留字与 `_`）且不与重叠作用域内的既有声明冲突，随后按偏移升序返回覆盖声明与全部引用的 `WorkspaceEdit`。非法名称或作用域冲突返回 `-32602`。
  - **Code Action 与自动导入（`codeActionProvider: true`）**：`textDocument/codeAction` 基于当前文档诊断生成确定性 Quick Fix（`E1018` 补齐或规范末尾换行、`E4009` 移除未使用导入、`E6201` 补齐 `@move(...)`），并在 `E4002` 命中工作区导出符号时生成自动导入（顶部插入 `import <mod>;` 并将调用改写为 `<mod>::<sym>`）。
  - **全管线总工作量预算与 32 位跨度**：文档分析管线在既有逐点配额之上新增统一总工作量预算（`DOCUMENT_TOTAL_WORK = 131072`），跨词法、解析、符号、类型、布局、所有权与索引累计扣费；超限时中止分析、丢弃局部诊断并发送状态通知（原因码 50）。`types::Span.length` 升级为 `u32`，消除长文档多记号跨度在 65535 字节处的截断（单 token 长度仍遵循 `lex.md` L-20 的 `E1020` 上限）。
- `bash test/gate/test_lsp_frame.sh both candidate` 用当前候选 Seed 和正式构建的 Win64 可执行文件在开放管道上核验握手、诊断、恢复及关闭。编辑器形状的握手夹具不算真实客户端验证；此入口也不是正式发布、审计镜像或自举固定点证据。
- Win64 使用 `lsp_vscode_check.cjs` 与 `lsp_neovim_check.py` 补充验证，命令见 [门禁脚本说明](../../test/gate/README.md#脚本)。分别归档各客户端实际执行的握手、同步、查询、诊断与退出断言。资源和正式发布取证另行通过相应门禁。

### 独立 Linux x86-64 构建与交付

- Linux x86-64 宿主上，用 `bash compiler/lsp/build.sh --target linux-x64 --native-compiler EXE --native-scanner EXE <仓库内输出目录>` 构建 `yak_lsp.elf`。该包装入口固定使用 `compiler/lsp/yak_lsp.yak` 为根，不启用审计镜像，也不执行 Seed 或接收预制 `YAK_RUNTIME_OBJ`。调用方须事先核验 Win64 编译器和扫描器的来源及摘要，设置能接收 EXE 路径并完整传递标准流和退出码的 `YAK_PE_RUNNER`；此运行器只用于构建器，语言服务本身由 Linux 直接执行。
- Bash、GNU coreutils 和 Python 使用 `versions.lock` 的共用条目；GNU GCC 目标须为 `x86_64-linux-gnu`，GCC、独立 GNU `as`、GCC 实际选择的 GNU `as` 和 GNU `ld` 须通过该文件的 ELF 版本锁。可用 `YAK_ELF_CC`、`YAK_ELF_AS`、`YAK_ELF_LD` 指定命令（默认 `gcc`、`as`、`ld`）。共享正式入口使用相同模块图和归属检查，从运行时源码链接静态 x86-64 ELF，入口须在可执行加载段内且无解释器。仅发布 `yak_lsp.elf` 与两行 `.yak_lsp.yak-root`；失败保留原产物或回滚，不提交部分产物。
- Linux 交付证据须记录源码、两枚构建工具、宿主工具和产物的身份，独立清冷构建比对 ELF 与归属标记的原始字节。用同一份发布入口产物直启开放管道、真实 Neovim 与 VS Code 客户端及 Linux 资源探针，保存原始命令、退出、日志及资源口径；Windows 私有提交量不能用 Linux RSS 替代。通过该边界不等于 T1 Linux CI、双目标自举或 Seed 退役。
