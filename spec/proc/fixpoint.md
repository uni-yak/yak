# fixpoint

## 元信息

- 名称：fixpoint（固定点收敛）
- 级别：流程
- 拒绝形态类别：门禁断言
- 状态：草案
- 依赖：`build.md`、`gate.md`、`status.md`、`../ir/ysm.md`、`../lang/symbol.md`

## 一、范围

1.1 本文规定自举固定点的三遍收敛定义、比对对象、语义对拍与撕裂检测。

1.2 固定点是自举编译器（`yakc-min` / `yakc-full`）"编译自身"达到逐字节稳定状态的证明（`seed.md` T2）。

## 二、三遍收敛

2.1 `C0` 为上一代编译器和同代模块扫描器组成的构建工具。T2 由 T1 点火产物提供 `C0`，后续升级由上一固定点产物提供。

2.2 三遍：

| 遍 | 输入 | 执行者 | 产物 |
|:---|:---|:---|:---|
| pass-1 | 同一待验收源码快照 | `C0` | `C1` |
| pass-2 | 同一待验收源码快照 | `C1` | `C2` |
| pass-3 | 同一待验收源码快照 | `C2` | `C3` |

2.3 T2 的三遍自编译产出 Win64 编译器和扫描器。对两个根逐单元比对 `C2` 与 `C3` 的 `.ysm` 与 COFF `.obj`，要求文件集及字节一致。第 2.5 条的 ELF 验证使用同一候选固定点，产出并运行 Linux 目标程序。

2.4 语义对拍：`C2` 与 `C3` 在同一目标 profile 对适用的 `test/ok/`、`test/bad/` 与 `test/gate/` 矩阵各自满足用例预期，同时产生相同输出、诊断与退出码（`gate.md` 2.2）。

2.5 `C2` 是候选固定点。T2 按 [门禁规格](gate.md) 2.3 用 `C2` 完成 Windows PE 与 Linux ELF 目标验证。完整门禁通过后，`C2`（= `C3`）晋升为新的固定点编译器，`C0` 与 `C1` 归档。

2.6 候选取证：在完整门禁前，可对同一源码快照、输入与锁定工具链按 2.1–2.4 隔离试运行。应记录工作树身份、冻结 Seed 和运行时摘要、目标与工具版本、遍次产物、实际比对范围和未执行项。T1 `C0` 可由冻结 Seed 点火；`C0` 之后不得回退到 Seed。单目标或仅定向语义回归的记录只证明其实际覆盖范围，不能代替双目标、正式 CI 或规格确认；产物不得晋升、发布或触发 Seed 退役。

## 三、比对对象

3.1 `.ysm`（MIR 审计镜像，`../ir/ysm.md`）的 SHA-256。

3.2 `.obj`（目标代码）的 SHA-256。

3.3 两者并列；任一不一致即未收敛。

3.4 `.ysm` 含随机地址 / mmap 布局的内容不得进入比对（`ysm.md` 5.2 禁止宿主指针）。

## 四、撕裂检测

4.1 `.ysm` format 4、5、6 的 `dependencies` 节按 `DependencyId` 记录每个直接依赖的 YKIF `content_digest`。摘要计算使用归零的摘要字段（`../ir/ysm.md` 4.1、`../lang/symbol.md` 10.8）。

4.2 加载 `.iface` 时的容器或版本校验失败按 `build.md` B-5 处理；固定点阶段比对 YSM 依赖表与实际加载接口时，摘要不一致为撕裂，按 `../ir/ysm.md` Y-7 拒绝。

4.3 固定点升级（依赖 / 工具 / 规格变更）须重跑三遍收敛；升为确认须通过 `status.md` 2.2 的完整门禁。

## 五、确定性前提

5.1 `LC_ALL=C`、`TZ=UTC`（`build.md` 2.1）。

5.2 `LocalId` / `BlockId` / 臂表按固定前序（`../ir/mir.md` 七）。

5.3 相同源码 + 相同依赖 `.iface` + 相同 layout / ABI profile 产生逐字节相同产物。

## 拒绝形态

| 编号 | 条件 |
|:---|:---|
| FP-1 | `C2` 与 `C3` 的 `.ysm` 或 `.obj` 不一致 |
| FP-2 | 语义对拍失败（诊断集合或退出码不同） |
| FP-3 | YSM 记录的依赖摘要与实际加载的 `.iface` 的 `content_digest` 不一致（Y-7，E7029） |
| FP-4 | 收敛未达成即改标确认 |
