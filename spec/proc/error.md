# error

## 元信息

- 名称：error（错误码体系）
- 级别：流程
- 拒绝形态类别：门禁断言
- 状态：确认
- 依赖：`../lang/symbol.md`、`../lang/base.md`、`../lang/lex.md`、`../lang/parse.md`、`../lang/name.md`、`../lang/sugar.md`、`../lang/layout.md`、`../lang/const.md`、`../lang/type/enum.md`、`../lang/type/union.md`、`../lang/type/option.md`、`../lang/type/result.md`、`../lang/owner.md`、`../target/emitter.md`、`error.def`

## 一、范围

1.1 本文规定错误码的编码规则、段定义、诊断协议与确定性。**具体码位、关联拒绝编号与描述的唯一真源为 `error.def`**。

1.2 `ErrorCode` 独立于 `BuiltinId`，不占固有符号分区（`symbol.md` 4.1）。

1.3 编码为 u16，格式 `E<千位><百位><两位序号>`：

- 千位 = 大阶段（0-9，编译管线顺序）
- 百位 = 子领域（0-9，阶段内语义细分）
- 两位序号 = 01-99（子领域内编号）

## 二、段定义

2.1 大段按**编译管线顺序**分配，禁止重排：

| 千位 | 大阶段 | 容量 |
|:---|:---|:---:|
| E0 | 通用 / 预留 | 990 |
| E1 | 词法 | 990 |
| E2 | 解析 | 990 |
| E3 | 脱糖 | 990 |
| E4 | 名字 / 作用域 | 990 |
| E5 | 类型 | 990 |
| E6 | 所有权 / 能力 | 990 |
| E7 | MIR / 发射 | 990 |
| E8 | 链接 | 990 |
| E9 | 运行时 / 库 | 990 |

2.2 每个大段内按子领域（百位）细分，每子领域 99 个码位。子领域划分的唯一真源为 `error.def`。

2.3 子领域的名称、所属大段、条目数和剩余容量均从 [错误码配置](error.def) 读取。含 `entry` 的子领域已有登记码位。

2.4 已声明且无 `entry` 的子领域全部预留。其 `reserve` 须覆盖序号 `01` 至 `99`。

2.5 新增错误码只能追加，不得重编号或复用已登记码位。新子领域从预留中申领，申领即冻结其码位布局。

## 三、配置源

3.1 `error.def` 是错误码的**唯一可编辑配置源**，登记大段、子领域、码位、关联规格引用与描述。

3.2 配置语法为逐行、固定字段顺序的声明式格式。首条有效指令为唯一的 `format 2`，其余只允许 `segment`、`entry` 与 `reserve`。禁止任意表达式、脚本和条件分支。

3.3 `segment` 声明支持两层：大段（无 `parent`）与子领域（带 `parent` 指向大段）。

3.4 每条 `entry` 必须显式写出子领域码、两位序号、关联规格引用（`ref`）与描述；生成器不得自动分配码位。

3.5 `ref` 为 `<规格文件>:<拒绝编号或章节>`，指向该错误的语义定义处。先相对 `error.def` 所在目录解析，如 `host.md:HS-1`、`../lang/type/enum.md:EN-1`。历史语言文档短名可回退到 `spec/lang/`，如 `lex.md:L-1`。解析不得依赖当前工作目录。

3.6 编号自描述：`E5001` = 类型(E5) > 隐式转换(E50) > 第 01 号；`E6102` = 所有权(E6) > 槽位状态机(E61) > 第 02 号。

3.7 生成器校验大段、子领域及码位唯一，子领域的 `parent` 已登记，码位在 `01` 至 `99`，`ref` 的文件与锚点均存在，描述非空。`entry` 按完整码位升序排列，每个子领域使用从 `01` 起的连续前缀，`reserve` 紧接已用序号并覆盖到 `99`。历史已登记的码位和 `ref` 须与 [历史基线](error_history.json) 一致，任一违反均拒绝生成。

3.8 编译器运行时不解析 `error.def`；加载由生成器产出的静态表。配置只在工具链更新或审计生成阶段进入构建流程。

## 四、诊断协议

4.1 诊断内部表示携带 `ErrorCode`(u16)、`Span`（`lex.md` 9.1）、类型/符号 id 与结构化参数。

4.2 诊断输出协议见 `diag.md`；默认输出终端文本，`--diag=jsonl` 输出 JSONL。

4.3 诊断不携带字符串；名称反查由 arena + `NameRef` 完成（`symbol.md` 7.1）。

4.4 错误码是编译的确定函数；相同输入产生相同错误码集合。

## 五、确定性

5.1 相同源码、依赖接口与目标 profile 产生相同错误码集合。

5.2 给定同样的输入和读取结果，错误码不依赖时间戳、进程信息或宿主路径。缺失依赖、无法读取已登记文件的诊断分别见 [构建规格](build.md) 和 [宿主规格](host.md)。

5.3 `error.def` 变更后，必须重新生成静态表并运行错误码回归；未通过摘要门禁不得编译。

## 六、拒绝形态

| 编号 | 条件 |
|:---|:---|
| ER-1 | 混用错误码与其他 id 域 |
| ER-2 | `error.def`、生成表与产物摘要不一致 |
| ER-3 | 错误码跨子领域重编号或复用已登记码位 |
| ER-4 | `ref` 引用的规格文件不存在 |
| ER-5 | 配置源含执行代码或隐式码位分配 |
