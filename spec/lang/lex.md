# lex

## 元信息

- 名称：lex（词法与编码基线）
- 级别：base / full
- 状态：草案
- 依赖：`symbol.md`、`base.md`

## 一、范围

1.1 本文规定源码字符编码、token 分类、字面量形态、保留字与上下文关键字、运算符记号、注释与 token 位置规则。

1.2 名字的语义规则（作用域、可见性、遮蔽）见 `name.md`；名字到 id 的映射见 `symbol.md`。

1.3 语法产生式与 token 序列到 AST 的解析见 `parse.md`。

1.4 本文允许 seed 下运行 min 词法组件的参考实现与测试；不确认 min/full 的目标代码能力。只实现 base 词法闭集，full 专属前缀、token、保留占位字与原语必须拒绝；需要语法或类型信息的 L-4 目标类型范围与 L-10 留给后续阶段，不由扫描器猜测。L-9（base 期类型位出现 `T?`）由解析期按 `parse.md` 的说明与 `base.md` R-24 以 E3008 拒绝，不在本表单列；其已登记的码位按 `../proc/error.md` 2.5 保留。

1.5 本轮参考组件的标识符字母限定 ASCII `A-Z` / `a-z`，数字限定 `0-9`；文本、字符和注释仍接受完整 Unicode 标量。`name.md` 的非 ASCII 名称字符分类与规范化尚未冻结，参考组件对该类名称按 L-16 拒绝，不将其登记为已实现能力。

## 二、字符编码

2.1 源码文件编码为 UTF-8；无 BOM。

2.2 行结束符统一为 `\n`（LF）；`\r\n` 在词法层归一化为 `\n`。

2.3 禁止 `\r` 单独出现作为行结束。

2.4 源码中的 Unicode 标量值范围 U+0000–U+10FFFF，排除代理对（U+D800–U+DFFF）。

2.5 BOM、非 UTF-8 字节序列、代理对均为拒绝形态（L-1）。

2.6 文件末尾必须有且仅有一个换行符。

## 三、空白与注释

3.1 空白字符：空格（U+0020）、水平制表（U+0009）、换行（U+000A）、回车（U+000D，归一化为 LF）。

3.2 行注释：以 `//` 开始，至行末结束；内容不参与 token 流。

3.3 块注释：以 `/*` 开始、`*/` 结束；支持嵌套；不参与 token 流。

3.4 注释内部的 `"`、`'` 等记号不产生字面量；注释在词法层完全消除。

3.5 文档注释（`///`、`/** */`）为 full 层形态；base 期出现为拒绝形态（L-2）。

## 四、Token 分类

4.1 token 分为六类：

| 类 | 说明 |
|:---|:---|
| 标识符 | 字母/下划线开头，后续字母/下划线/数字；携带 `NameId + Span` |
| `HashName` | `#` 紧贴标识符形成的 callable 名；携带底层 `NameId + Span`，只在声明 `CallableName` 位合法 |
| 字面量 | 整数、布尔、字符、字符串、full 层 `null` |
| 保留字 | 见第五节 |
| 运算符与分隔符 | 见第七节 |
| 固有 `@` 项 | `@` 加已登记原语或注解名；token 直接携带 `BuiltinId` |

4.2 token 流不携带空白与注释；每个 token 携带源位置（文件号、字节偏移、行、列）。普通标识符 token 与 `HashName` 均携带由本次扫描 intern 的底层 `NameId`；同一单元内相同 UTF-8 字节串必须取得相同 `NameId`。`HashName` 的 Span 含前缀 `#`，但 `#` 不进入名称字节区。

4.3 源位置用于诊断；不进入 AST 语义（`symbol.md` 1.3）。`NameId` 仅持续到名字解析完成，不能作为已解析 AST、MIR 或 YSM 的引用身份。

4.4 `_` 单独出现为通配 token，仅在 match pattern 位合法（`parse.md` 六）；不得作普通绑定名或标识符。`_` 开头后随字母 / 数字 / 下划线为普通标识符。

4.5 seed 参考前端的固定 TokenKind：`0=ident`、`1=hash_name`、`2=int_lit`、`3=bool_lit`、`4=char_lit`、`5=str_lit`、`6=keyword`、`7=op`、`8=builtin`、`9=eof`、`10=wildcard`。Token 为 `{kind:u8, span:Span, payload:u64, integer_suffix:u8}`。整数 payload 保存无符号幅值；后缀为 `0=无`、`1=u8`、`2=u16`、`3=u32`、`4=u64`、`5=i8`、`6=i16`、`7=i32`、`8=i64`；其他 token 的后缀必须为零。有符号 MIN 的正幅值留给 check 结合一元负号判定，扫描器不得提前拒绝。

4.6 KeywordId 按 5.1 从零编号（共 21 项）；`true` / `false` 输出 bool_lit，payload 为 1 / 0，不分配 NameId。OpId 按以下顺序从零编号：`:: == != <= >= && || << >> => .. + - * / % < > ! & | ^ = . : ? ( ) { } [ ] , ;`。该编号不是 BuiltinId，也不作为 YSM opcode。

4.7 字符串 payload 为扫描次序从零分配的 static_index，每个字面量独立记录 `{offset:u32,length:u32}` 并引用结果中的静态字节区；允许空串、内嵌 NUL 与相同长度的不同内容。该池是前端字节资产，尚未形成 YSM 布局或类型签名。

4.8 扫描返回 token、NameTable、静态池和结构化诊断；先校验整个文件编码与换行，再按源码顺序扫描。每阶段出现首个错误立即停止，清空 token 流且不产出 EOF，诊断保留 ErrorCode 与 Span。调用方必须先检查诊断，禁止将失败结果继续解析。分配失败仍通过 AllocError 传播，不伪装为词法错误。

## 五、保留字

5.1 保留字（base 生效，任意位置禁止作标识符）：

```text
function  let  var  const  if  else  elseif  while  break  continue  return
match  enum  struct  true  false  import  export  foreign  out  as
```

5.2 保留占位字（base 期出现即拒绝；full 层启用）：

```text
loop  unsafe  interface  impl  implements  for  in  is  type  never  null
```

5.3 保留字与占位字清单的唯一真源为本节；`symbol.md` 2.9 与 `name.md` 2.2 引用本节，不重复登记。

5.4 保留字不进入 `NameTable`，不分配 `NameId` 或 `BuiltinId`（`symbol.md` 2.9）。

## 六、上下文关键字

6.1 上下文关键字在词法层输出为标识符 token；仅限下列语法位具有关键字语义，其余位置为合法标识符：

| 上下文关键字 | 关键语义位 | 普通标识符位 |
|:---|:---|:---|
| `Read` | 能力后缀位（`&T:Read`） | 其余位置 |
| `Write` | 能力后缀位（`&T:Write`） | 其余位置 |
| `ReadWrite` | 能力后缀位（`&T:ReadWrite`） | 其余位置 |

`move` 不是上下文关键字：参数声明不使用 `move` 前缀，转移动作只写作 `@move(e)`；其在所有标识符位均为普通标识符。

6.2 不引入 `ref`、`val` 关键字（`base.md` 3.5）：引用记号固定为 `&`，绑定记号固定为 `let` / `var` / `const`。不引入 `Ok` / `Err` / `Some` / `None` 构造器。

6.3 `out` 为保留字（非上下文关键字），在槽位声明位与调用点前缀位具有关键字语义；不可作标识符。

## 七、运算符与分隔符

7.1 运算符与分隔符清单（base）：

```text
+  -  *  /  %
==  !=  <  <=  >  >=
&&  ||  !
&  |  ^  <<  >>
=  =>
.  ::  :  ?  as  ..  @
(  )  {  }  [  ]  ,  ;
```

full 在不改变 base token 含义的前提下追加 `?.`、`??` 与 `..=`；`is` 为 full 占位字（5.2）。`?.`、`??` 与 `..=` 均作为最长匹配 token，不拆分为 `?` 加 `.`、两个 `?` 或 `..` 加 `=`。

7.2 分隔符用途总表（base + full）：

| 分隔符 | 用途 | 层 |
|:---|:---|:---|
| `::` | 路径分隔（模块路径 `A::B::C`、enum 标签路径 `Color::Red`） | base |
| `.` | 成员访问（struct 字段 `obj.field`、方法接收者 `obj.method()`） | base |
| `?.` | 可空成员或可空方法访问 | full |
| `??` | 可空载体回退 | full |
| `=>` | match 臂分隔（`Pattern => Block`，base）；full 无捕获匿名函数（`(ParamList) => Block`，S-21） | base / full |
| `<>` | 泛型实参（`function<T>(args)`、`Array<T>`，类型位置） | full |
| `()` | 函数调用、enum 标签构造 / payload 绑定、分组 | base |
| `[]` | 数组索引、切片、定长数组类型 `[T; N]` | base |
| `{}` | 块、struct 字段列表 | base |
| `,` | 列表分隔（参数、arm、字段） | base |
| `;` | 语句终止 | base |
| `:` | 类型标注、返回类型、能力后缀 | base |

路径与成员访问的区分：`::` 只用于路径（编译期可解析的限定名），`.` / `?.` 只用于运行期成员访问。三者不交叉。

7.3 运算符优先级与结合性见 `parse.md`；本文只规定 token 切分。

7.4 最大匹配原则：词法从当前位置尝试匹配最长的合法 token。`::` 优先于 `:`；`?.` 优先于 `?` 与 `.`；`??` 优先于 `?`；`==` 优先于 `=`；`=>` 优先于 `=`；`!=` 优先于 `!`；`<=` / `>=` 优先于 `<` / `>`；`<<` / `>>` 优先于 `<` / `>`；`..` 优先于 `.`。

7.4.1 full 泛型类型参数上下文例外：当解析器处于 `GenericArgs` 的关闭状态时，`>>` 拆为两个 `>`，`>=` 拆为 `>` 与 `=`；离开该上下文后恢复最大匹配。该拆分只由括号深度与泛型上下文触发，不改变表达式中的移位/比较运算。

7.5 `@` 为受位置约束的前缀记号；`@` 后必须紧跟已由 `symgen` 登记且类别为 primitive 或 annotation 的固有名称，且不得用于用户标识符（L-3）。词法器以静态字节分派直接产出对应 `BuiltinId`，不创建普通 `NameId` token；表达式位置只接受类别为 primitive 的项（如 `@move(e)`、`@len(s)`、`@wrap_mul(a, b)`），full 层模块项前位置只接受类别为 annotation 的项（如 `@inline()`、`@align(8)`）。裸 `move` / `copy` / `clone` / `drop` / `push` / `len` / `wrap_add` / `wrap_sub` / `wrap_mul` 为普通标识符。

7.6 `#` 不作为独立 token。词法器遇到 `#` 时，仅有两条合法路径：`r#"..."#` 的原始字符串扫描（8.12），或 `#` 后**无空白、无注释且紧贴非保留字标识符**时产出 `HashName`。`HashName` 标记 `function #foo(...)` / `foreign #write(...)` 的零分配契约；其底层名称为 `foo` / `write`，不分配新的 `NameId` 或 `BuiltinId`，也不进入修饰名（`abi-win.md` 五）。`#` 后有 trivia、后随保留字 / 非标识符或写作 `#[...]` 时为 L-16；形成的 `HashName` 是否处于合法语法位由 parser 按 P-15 判定。

## 八、字面量

8.1 整数字面量：

| 形式 | 说明 |
|:---|:---|
| `0b` 前缀 | 二进制 |
| `0o` 前缀 | 八进制 |
| `0x` 前缀 | 十六进制 |
| 十进制 | 默认 |
| 后缀 | `u8` / `u16` / `u32` / `u64` / `i8` / `i16` / `i32` / `i64` |

8.2 整数字面量定型由上下文决定；无法唯一定型时必须显式标注或后缀（`base.md` 4.7）。不提供默认整数宽度。

8.3 整数字面量溢出（超出目标类型范围）为拒绝形态（L-4）。

8.4 布尔字面量：`true` / `false`（保留字）。

8.5 引号形态总表：

| 界定符 | 语义 | 层 | 类型 | 转义 | 插值 | 跨行 | UTF-8 保证 |
|:---|:---|:---|:---|:---|:---|:---|:---|
| `'...'` | 字符（单 Unicode 标量） | base | `char` | 支持 | 否 | 否 | — |
| `"..."` | 文本（UTF-8 字节视图） | base | `&[u8]` | 支持 | 否 | 否 | 是 |
| `b'...'` | 字节（单字节） | full | `u8` | 支持 | 否 | 否 | — |
| `b"..."` | 字节串（任意字节序列） | full | `&[u8]` | 支持 | 否 | 否 | 否 |
| `r"..."` | 原始字符串（所见即所得） | full | `&[u8]` | 否 | 否 | 是 | 是 |
| `` `...` `` | 模板字符串（多行 + 插值） | full | `string` | 最小子集 | `{expr}` | 是 | 是 |

8.6 共享转义序列（`'...'`、`"..."`、`b'...'`、`b"..."` 共用）：

| 转义 | 含义 | 字节值 |
|:---|:---|:---|
| `\n` | 换行 | 0x0A |
| `\r` | 回车 | 0x0D |
| `\t` | 制表 | 0x09 |
| `\0` | NUL | 0x00 |
| `\\` | 反斜杠 | 0x5C |
| `\'` | 单引号 | 0x27 |
| `\"` | 双引号 | 0x22 |

8.7 域专属转义：

| 转义 | 适用形态 | 语义 |
|:---|:---|:---|
| `\u{H...}` | `'...'`、`"..."`、`b"..."` | Unicode 标量（1–6 位十六进制，值域 0x0–0xD7FF ∪ 0xE000–0x10FFFF，禁代理对）；`'...'` 中为单标量 `char`；`"..."` 与 `b"..."` 中编码为 1–4 字节 UTF-8 |
| `\xNN` | `b'...'`、`b"..."` | 原始字节（2 位十六进制，00–FF 全域）；产出 1 字节 |

8.8 字符字面量 `'...'`（base）：`'` ... `'` 包裹单个 Unicode 标量值或一个解码后恰占一个标量的转义。支持 8.6 共享转义 + `\u{H...}`；不支持 `\xNN`。类型 `char`。空、多标量、未闭合按 L-22；代理对按 L-1（源码编码）或 L-6（Unicode 转义）拒绝。

8.9 文本字面量 `"..."`（base）：`"` ... `"` 包裹 UTF-8 字节序列，支持 8.6 共享转义 + `\u{H...}`；不支持 `\xNN`。词法层保证内容为合法 UTF-8（源码即 UTF-8，`\u{}` 编码为 UTF-8 字节）。类型 `&[u8]`（指向静态存储，`base.md` 4.2）。裸换行为拒绝（L-5）；`\n` 转义合法。

8.10 字节字面量 `b'...'`（full）：`b` 紧随 `'` 构成前缀；`b'` ... `'` 包裹单个字节。支持 8.6 共享转义 + `\xNN`（全域 00–FF）；不支持 `\u{H...}`（单 `u8` 放不下多字节 UTF-8 编码）。类型 `u8`。多字节、空、`\u{}` 为拒绝（L-12）。

8.11 字节串字面量 `b"..."`（full）：`b` 紧随 `"` 构成前缀；`b"` ... `"` 包裹任意字节序列。支持 8.6 共享转义 + `\xNN`（全域）+ `\u{H...}`（编码为 UTF-8 字节，1–4 字节）。`\xNN` 产出 1 个原始字节；`\u{H...}` 产出 1–4 个 UTF-8 编码字节——二者语义不同，可混用。类型 `&[u8]`；不保证 UTF-8 合法（可含非 UTF-8 字节如 `\x80`）。裸换行为拒绝（L-5）。

8.12 原始字符串 `r"..."`（full）：`r` 紧随 `#`* 与 `"` 构成前缀。产生式：`raw-open = "r" { "#" } '"'`；`raw-close = '"' { "#" }`。开头与结束的 `#` 数量必须相同（N = 0–3）。不解析任何转义、不插值；内容只排除匹配的结束界定符。可跨行（保留换行字节）。类型 `&[u8]`；内容为源码切片，保证合法 UTF-8（2.1）。`r` 后须紧随 `#` 或 `"`，否则 `r` 为普通标识符。未闭合或 `#` 不匹配为拒绝（L-13）。

8.13 模板字符串 `` `...` ``（full）：反引号包裹；可跨行，保留换行字节。转义最小集：`\\`、`` \` ``；不支持 `\n` 等（换行按原样保留）。`{{` / `}}` 为字面花括号；单个 `{` 开启插值洞 `{expr}`。插值范围由词法器定位后交解析器重新调用同一扫描器解析。类型 `string`（owning，full）；脱糖见 `sugar.md` S-24。未闭合为拒绝（L-14）；插值洞未闭合 `}` 为拒绝（L-15）。

8.14 `b` / `r` 前缀消解（maximal munch）：`b` 紧随 `'` → `b'...'`；`b` 紧随 `"` → `b"..."`；`r` 紧随零至三个 `#` 后再紧随 `"` 才进入 raw-string 扫描。`r#` 后若未形成 `r#*"`，则 `r` 按普通标识符扫描，后续 `#` 按 7.6 处理。`b` / `r` 前缀与引号之间不得有空白或注释。

8.15 浮点字面量在 base 期禁止（`base.md` 3.7）；出现 `.` 后随数字且非方法调用位时为拒绝形态（L-7）。

8.16 `null` 是 full 层唯一的可空字面量。它只在预期类型为 `T?` 的位置产生 null carrier 状态；base 期出现即为拒绝形态（L-8）。

## 九、token 位置规则

9.1 每个 token 携带文件编号、文件内字节偏移和字节长度。文件编号为 `u16`，偏移为 `u32`，单个 token 最大为 65535 字节（L-20）。C 种子扫描器用 `u16` 保存 token 长度，min 前端的共享跨度用 `u32` 保存长度，以容纳跨多个 token 的 AST 和诊断范围。

9.2 `&&` 在前缀位（表达式起始）拆分为两个借用记号 `&` + `&`；在二元位（操作数之间）为逻辑与单 token（`base.md` 3.8）。

9.3 `:` 用于类型标注位、返回类型位与能力后缀位；模块路径用 `::`。能力后缀只在访问位置的引用类型归约之后有效（`base.md` 3.8）。

9.4 `?` 为表达式后缀传播，只作用于 `T!E`；类型尾缀 `T?` 为 full 层可空载体。`?.` 与 `??` 是 full 层独立 token，只作用于 `T?`，不得按单字符 token 拆分。

9.5 `!` 两用：类型位构成 `T!E` 载体；表达式位只作逻辑非及 `!=` 组合。表达式后缀 `value!` 不存在。

9.6 `|` 三用：ErrorSpec 括号内构成错误集 `T!(E1 | E2)`；full 类型位构成普通联合 `A | B`；表达式位为按位或。位置区分由 `parse.md` 产生式决定。

9.7 `..` 仅用于索引位 `[a..b]`；出现在其他位置为拒绝形态（L-10）。

9.8 `&` 在函数名位产出函数静态引用（类型 `&function(P): R`），与借用视图的 `&` 同形但语义不同（`base.md` 3.8）。区分由 `parse.md` 产生式决定。

9.9 `@` 后的已登记名称与 `@` 组合为携带 `BuiltinId` 的原语或注解 token；未登记名称、`@` 单独出现或后随非标识符均为拒绝形态（L-11）。

## 十、确定性

10.1 相同源码文件与相同编码设置产生相同 token 流。

10.2 token 流的顺序是解析的确定函数（`symbol.md` 1.7）。

10.3 词法层不依赖文件系统状态、时间戳或进程信息。

## 十一、拒绝形态

| 编号 | 条件 |
|:---|:---|
| L-1 | 非 UTF-8 字节序列、BOM、代理对 |
| L-2 | base 期出现文档注释（`///`、`/** */`） |
| L-3 | `@` 被写作用户标识符的组成部分 |
| L-4 | 整数字面量溢出目标类型范围 |
| L-5 | 字符串字面量含裸换行 |
| L-6 | 字面量含非法转义序列 |
| L-7 | base 期出现浮点字面量 |
| L-8 | base 期出现 `null` |
| L-10 | `..` 出现在非索引位 |
| L-11 | `@` 单独出现、后随非标识符或后随未登记的原语 / 注解名 |
| L-12 | `b'...'` 含多字节、空或 `\u{}`（字节字面量须单字节且只用 `\xNN`） |
| L-13 | 原始字符串 `r"..."` 未闭合或 `#` 数量不匹配 |
| L-14 | 模板字符串 `` `...` `` 未闭合 |
| L-15 | 模板插值洞 `{...}` 未闭合 `}` |
| L-16 | `#` 未形成 `HashName`（后随 trivia / 非标识符）、出现 `#[...]`，或出现 `$`、`~` 等未登记源字符 |
| L-17 | 单独 CR 行结束 |
| L-18 | 文件末尾不是有且仅有一个换行 |
| L-19 | 块注释未闭合 |
| L-20 | 单个 token 字节长度超过 65535 |
| L-21 | 整数进制、数字或后缀形态非法 |
| L-22 | 字符为空或多标量，或字符/文本字面量未闭合 |
