# compiler/min/src/emit

## 职责

消费已检查的 MIR 与目标 profile，产出 Windows x64 COFF 或 Linux x64 ELF64 对象（`../../../../spec/target/emitter.md`）。
base 期为栈槽模型，每个 `LocalId` 固定占一个 `[rbp - N]` 槽，不做寄存器分配。

## 输入 / 输出

- 输入：`mir::MirModule` + `LinkTable`（符号名与 LinkId 由调用方提供）+ 目标 profile
- 输出：`EmitResult`（成功时 `bytes` 为完整 COFF 对象；失败时 `bytes` 为空且 `code` 为拒绝码）

符号名不在 MIR 中（MIR 按规格不保留 `NameId`/`ScopeId`），因此由本目录的 `LinkTable` 承载：

```yak
export struct LinkSymbol { def: u32, kind: u8, name: u8[] }   // kind: 0=本地函数 1=外部 2=数据
export struct LinkTable { symbols: LinkSymbol[] }
```

## 文件组织

| 文件 | 内容 |
|:---|:---|
| `pe.yak` | x86-64 机器码编码原语：REX / ModRM / 立即数 / 栈槽读写 / 各指令字节序列 / 跳转回填 |
| `x86_validate.yak` | 校验定稿函数字节，识别指令边界与内联跳转表，并拒绝子集外或非规范编码 |
| `coff_state.yak` | 共享发射状态、栈槽规划、操作码与搬运原语 |
| `coff_call.yak`、`coff_place.yak` | 调用 ABI、地址、聚合槽与拥有值销毁 |
| `coff_inst.yak`、`coff_func.yak` | 指令与终结指令降级、函数序言、块发射和回填 |
| `coff_layout.yak` | 目标布局构建、静态只读区拼装与按需运行时符号登记 |
| `coff.yak` | 对象发射入口与 COFF 头、节、重定位和符号表装配 |
| `elf_backend.yak`、`elf.yak` | 将 System V 函数布局绑定到 ELF64 符号和 RELA 重定位，并验证容器 |

`pe.yak` 只认寄存器编号与槽偏移，不含 MIR 语义；`coff.yak` 只做语义映射，字节形态全部下沉到 `pe.yak`。
两文件的常量一律以 `export function` 形式导出（模块私有的 `const` 跨模块不可见）。

## 目标入口

`bash tools/link.sh LEAF.yak ROOT.yak --target linux-x64 --objects-only --emit-ysm` 交付 `.o`、`.iface` 与 `.ysm`。在 Linux x86-64 可省略 `--objects-only` 以链接和运行 `.elf`。主驱动的选择参数为 `--target=linux-x64`，对应接口 profile `0x00010002` 与 YSM profile `0x0102`。

System V 共用局部布局与机器码定稿逻辑。切片的指针和长度可跨第六个寄存器和栈。纯整数聚合按机器字分配，寄存器不足时整值落栈，较大的返回值走隐藏地址。可执行入口处理清理之后的返回状态。调用约定见 [System V AMD64 psABI](https://gitlab.com/x86-psABIs/x86-64-ABI)。

## 栈槽规划

```yak
export struct SlotPlan { slots: u32[], widths: u8[] }
export function plan_slots(func: &mir::MirFunction:Read, types: &typecheck::TypeTable:Read): SlotPlan!AllocError
```

- 每个局部一律占 8 字节槽（保证 8 字节对齐），实际读写宽度另记于 `widths`。
- 槽偏移从 `rbp - 8` 起递增；`frame_size` 向上取 16 字节对齐。
- `width_of(widths, local)` 给出该局部的访问宽度（1/2/4/8）。

## 指令选择表（MIR → x86-64）

`lower_inst` 按 opcode 分发；未识别的 opcode 不静默跳过：先记入 `Emitter.rejected`（保存首个未识别 opcode），
再写入 `int3` 占位；装配前 `emit_object` 检查该标记并整体拒绝（归 EM-4），因此绝不会带着 `int3` 成功返回。

### 常量

| MIR opcode | 值 | x86 序列 |
|:---|:---|:---|
| `const_int` | 1 | 以值类型宽度发射 `mov` 立即数，再写对应宽度的栈槽。常量零用 `xor eax,eax` |
| `const_bool` | 2 | 一字节常量与栈槽，值为 0 或 1 |
| `const_bytes` | 3 | `lea rax, [rip+静态偏移]` → 指针存 `[rbp-N]`；`mov rax, imm64` 存长度到 `[rbp-N+8]` |
| `const_aggregate` | 4 | `lea rax, [rip+静态偏移]` 取池条目地址 → 按剩余字节从 `{8,4,2,1}` 取最大可行宽度逐块 `load_base` + `store_slot_off`，整块复制进目标聚合槽 |

`const_bytes` 的 16 字节切片槽与 `.rdata` 重定位见下文「静态字节池与 .rdata」。`const_aggregate` 与 `const_bytes` 共用同一数据节与同一 `$s<index>` 数据符号机制：前者真的搬运字节，后者只登记视图，两者互不替换。贪心分块保证非 8 倍数尺寸（如 6 字节的 `[u16; 3]`）不会发出越读池外或 `.rdata` 节尾的 8 字节块；槽位缺失、字节长度为 0、目标不是聚合块或长度超过规划槽宽一律走未支持形态拒绝。结果是本地聚合槽，不经返回寄存器与实参 ABI，EM-6 边界不变。

### 算术（溢出时跳 trap）

| MIR opcode | 值 | x86 序列 |
|:---|:---|:---|
| `add` | 16 | 按类型宽度执行 `add`，有符号用 `jo`、无符号用 `jb` 跳转到 trap |
| `sub` | 17 | 按类型宽度执行 `sub`，有符号用 `jo`、无符号用 `jb` 跳转到 trap |
| `mul` | 18 | 有符号 `imul` 加 `jo`；无符号用 `imul` 后检查目标宽度，64 位按操作数的符号位修正乘积高半部 |
| `div` | 19 | 检查除零和有符号 `MIN / -1` 后用 `idiv`。无符号 64 位除法将高位设为 1 的除数单独处理，其余由半个被除数的商余恢复全宽结果 |
| `rem` | 20 | 除零检查；有符号 `MIN % -1` 直接取零，否则按符号性除法并取 `rdx` |
| `neg` | 21 | 将源值复制到目标槽后按类型宽度取负；有符号用 `jo`、无符号用 `jb` 跳转到 trap |

### 回绕算术（不得发溢出跳转）

| MIR opcode | 值 | x86 序列 |
|:---|:---|:---|
| `wrap_add` | 22 | `add`（无 `jo`） |
| `wrap_sub` | 23 | `sub`（无 `jo`） |
| `wrap_mul` | 24 | `imul`（无 `jo`） |

`is_wrap_arith` / `wrap_base` 给出回绕语义判定：wrap 运算只允许映射到对应基运算，误发溢出跳转即 EM-5。

### 位运算与移位

| MIR opcode | 值 | x86 序列 |
|:---|:---|:---|
| `bit_and` | 32 | `and` |
| `bit_or` | 33 | `or` |
| `bit_xor` | 34 | `xor` |
| `shl` | 35 | `mov rcx, n; shl cl` |
| `shr` | 36 | `mov rcx, n; shr cl`（无符号）/ `sar cl`（有符号） |

### 比较

| MIR opcode | 值 | 生成形式 |
|:---|:---|:---|
| `eq` | 48 | `je` |
| `ne` | 49 | `jne` |
| `lt` | 50 | `jl`（有符号）/ `jb`（无符号） |
| `le` | 51 | `jle` / `jbe` |
| `gt` | 52 | `jg` / `ja` |
| `ge` | 53 | `jge` / `jae` |

比较指令执行 `cmp` 后先写 `eax = 1`，条件成立时跳过清零指令，否则写 `eax = 0`。有符号下标用 `cmp reg, 0` 与 `jl` 进入越界处理。
`cmp_condition(opcode, is_signed)` 给出条件码（CC）：eq/ne 与符号性无关，lt/le/gt/ge 必须按类型选码，
有符号与无符号混用即 EM-5。本地无载荷枚举的相等比较仅以 1 或 2 字节标签执行；所有标签均携带等宽内建整数、布尔或字符载荷的本地枚举，先比较标签，仅标签相同时按载荷宽度比较活动值。任意数量的标签携带等宽的上述标量载荷、其余标签无载荷时，只有活动标签相同且为载荷标签才读取载荷；相同的无载荷标签直接相等。等宽载荷与空标签混合的枚举选择数量较少的一侧生成分支，代码量及最坏运行时间随两者较小数量线性增长；编译期扫描仍随变体总数线性增长，仅混合枚举需要保存较少一侧的跳转位置，不再为所有标签分配临时数组。不同宽度的内建标量载荷按活动标签分派，在共同载荷偏移处按对应宽度读取；异宽路径的代码量及最坏运行时间随载荷标签数量线性增长。嵌套枚举、其他名义类型及内建 `AllocError` 的比较暂按 EM-4 拒绝；不以首个机器字或整个内存表示代替。

### 转换

| MIR opcode | 值 | 生成形式 |
|:---|:---|:---|
| `cast` | 64 | 按源局部类型的符号性选择宽化零扩展或符号扩展；窄化按目标宽度存储 |

### 调用

| MIR opcode | 值 | x86 序列 |
|:---|:---|:---|
| `call_local` | 144 | 实参装 rcx/rdx/r8/r9；`call rel32` 占位 → 重定位 |
| `call_far` | 145 | `ImportRef`（`b=ExportId`、`c=DependencyId`）经 `import_symbol_def` 合成高位键，`CallSite.symbol` 指向 `yak$<依赖模块>$f<ExportId>` 外部符号 |
| `call_foreign` | 147 | 同上，目标为外部符号（UNDEF） |

调用点以 `CallSite { at, symbol, kind }` 记录，统一在装配阶段产出 `IMAGE_REL_AMD64_REL32` 重定位。

实参按寄存器序号展开：标量占一个整型实参；`&[u8]` 切片占两个整型实参，先指针（`[rbp-N]`）后长度（`[rbp-N+8]`），
与运行时 `yak_rt_write(const u8* ptr, u64 len)` 的契约一致。展开后放不进 `rcx/rdx/r8/r9` 四个寄存器时，
`lower_call` 返回 4294967295 哨兵，`lower_inst_call` 据此判为未支持形态并整体拒绝（EM-4），绝不静默少传实参。
ABI 展开只发生在发射层；MIR 的调用指令始终只记录实参 LocalId。被调方序言由 `spill_params` 与上述展开严格互逆：把 rcx/rdx/r8/r9 回填到形参局部栈槽，切片展开为相邻两寄存器（先指针后长度）；形参超过四个寄存器窗口时设 `rejected=255` / `reject_kind=4`，按 EM-4 拒绝，不静默丢弃入参。跨单元调用的实参由根单元装寄存器、依赖单元在序言回填，因此 `call_far` 链接后能取到正确值。

### 终结指令

| MIR 终结 opcode | 值 | x86 序列 |
|:---|:---|:---|
| `br` | 192 | `jmp rel32`（块内回填） |
| `branch` | 193 | `mov rax, [rbp-A]; test rax, rax; jne then; jmp else` |
| `ret` | 194 | 有返回值时 `mov rax, [rbp-V]`；`add rsp, frame_size; pop rbp; ret` |
| `trap` | 195 | `int3` |

块间跳转先发 `rel32` 占位并登记 `BlockFixup`，等函数内全部块布局完成后按目标块偏移统一回填；
trap 目标单独记录 `trap_fixups`，由 `resolve_fixups` 收尾。

## COFF 对象布局

按 `../../../../spec/target/pe.md` 的物理顺序写出：

1. **文件头**：`Machine = 0x8664`（`machine_amd64()` = 34404）、`NumberOfSections = 3`、`TimeDateStamp = 0`、
   `PointerToSymbolTable` / `NumberOfSymbols` 回填真实值，`SizeOfOptionalHeader = 0`。
2. **节表**（3 × 40 字节，从偏移 20 开始）：

   | 节 | 属性 | 值 |
   |:---|:---|:---|
   | `.text` | 读 + 执行 | 1610612768 (0x60000020) |
   | `.rdata` | 读 | 1073741888 (0x40000040) |
   | `.data` | 读写 | 3221225536 (0xC0000040) |

   节名为 8 字节定长，短名右侧补 0。
3. **`.text` 内容**：逐函数顺序拼接机器码，函数入口偏移记入 `FunctionLayout.text_offset`。
4. **`.rdata` 内容**：`MirModule.static_bytes` 原样拼接，不做对齐填充；每个静态条目的偏移取
   `MirModule.statics[i].offset`，因此节内偏移与 MIR 静态池一一对应。`.data` 仍为空节。
5. **重定位表**：紧跟 `.rdata`，每条 10 字节（`地址 u32` + `符号下标 u32` + `类型 u16`）；
   调用点与静态数据引用一律 `rel_rel32()` = 4（`IMAGE_REL_AMD64_REL32`）。数据引用站点来自
   `FunctionLayout.data_refs`（`lea` 的 4 字节位移字段），符号下标为「链接表符号数 + 静态条目下标」。
6. **符号表**：紧随重定位表，按 LinkId（`LinkSymbol.def`）稳定升序排列；同一 LinkId 保持登记先后次序。
   每条 18 字节，名字 8 字节内联（短名右侧补 0）。已定义符号的 `value` 回填该函数在 `.text` 内的入口偏移，
   节号为 1，类型为 0x20（函数）；外部符号节号为 0（无节引用）且存储类为 external；
   本对象内部函数（kind 0）为 STATIC，导出函数、入口别名与外部引用为 EXTERNAL。
   每个静态条目追加一条数据符号（名字 `$s<下标>`、节号 2、类型 0x00、存储类 STATIC、值取 `.rdata` 内偏移），
   排在链接表符号之后，供 `lea` 重定位引用。
7. **字符串表**：紧随符号表。超过 8 字节的符号名在符号名处写 4 字节零 + 4 字节相对字符串表起点的偏移；
   字符串表首 4 字节为包含自身的总长度，正文按符号次序拼接「以 0 结尾的名字」。同一次装配中不出现长名时
   整张表省略，保持短名对象的既有字节布局。长名不再被拒绝，也不会写出偏移 0 的坏条目。

`assemble` 在重定位无法施加或符号无法装配时返回空字节；合法 COFF 头至少 20 字节，因此空字节唯一表示失败，
`emit_object` 据此拒绝，绝不返回半成品对象。

## 静态字节池与 `&[u8]` 视图

字符串字面量在 MIR 里是 `const_bytes`（opcode 3，操作数为静态池下标），类型是 `&[u8]`。
切片局部按**胖指针**占 16 字节栈槽：低 8 字节（`[rbp-N]`）放指针、高 8 字节（`[rbp-N+8]`）放长度；
`plan_slots` 对切片局部加 16 字节，`widths` 仍记 8（宽度描述的是标量读写宽度，不是槽宽）。

`const_bytes` 的降级序列：

```
lea  rax, [rip + 静态偏移]     ; 4 字节位移字段登记 DataRef，装配期转 REL32 重定位
mov  [rbp-N], rax              ; 指针
mov  rax, <静态条目长度>
mov  [rbp-N+8], rax            ; 长度
```

- 静态条目按 `MirModule.statics` 顺序在 `.rdata` 内排布，偏移直接取条目的 `offset`（与 `static_bytes` 对齐），
  不因发射阶段的遍历顺序而改变，保证相同 MIR 产出相同对象。
- 数据符号名固定为 `$s<十进制下标>`，不进 `LinkTable`，由 `build_symbols` 按静态条目顺序追加；
  重定位的符号下标为 `@len(table.symbols) + 下标`，因此链接表符号始终排在数据符号之前。
- `validate_reloc_sites` 对数据引用同样按 REL32 校验站点范围；`emit_relocs` 找不到数据符号即 EM-1。

顶层 `const S: &[u8] = "..."` 的全局常量视图已接入：常量在检查阶段求值为静态字节条目，
引用点由 `lower_module_const` 的 `kind == 4` 分支发 `const_bytes`（opcode 3），按胖指针取值，
最终仍走 `.rdata` + `lea` 重定位；链接后真实打印由 `examples/global_const.yak` 的端到端用例覆盖。
`parse_file` 只在不需要静态池的测试/探针路径使用，真实入口（`main.yak`、`check/pipeline.yak`）都走
`parse_lexed`，静态池随 `LexResult` 进入 `AstPool`。

## 重定位规则

- 只引用已登记 LinkId 的目标；未登记即 EM-1，不得生成悬空重定位。
- 静态数据引用引用本对象自动生成的数据符号，符号下标必须落在符号表范围内，否则 EM-1。
- 位宽必须与类型相符：`rel_rel32`/`rel_addr32nb` 为 4 字节，`rel_addr64` 为 8 字节；不符即 EM-3。
- 站点必须完整落在函数机器码范围内（`reloc_site_legal`）；越界或不足宽度即 EM-3。
- 重定位按节内偏移升序输出。

## 拒绝形态

| 码位 | 含义 | 触发点 |
|:---|:---|:---|
| `e_em1()` = 8002 | EM-1 链接符号未定义 | `validate_links`（def 0 / 空名）、`validate_call_targets`、`validate_symbols`（DefId 不在对象布局中） |
| `e_em2()` = 8003 | EM-2 重复定义 | `validate_links`（同一 LinkId 出现两次） |
| `e_em3()` = 8004 | EM-3 重定位失败 | `validate_reloc_sites`、`emit_relocs` |
| `e_em4()` = 8005 | EM-4 目标格式不支持 | `emit_object`（profile 非 `profile_win64_pe()`）、`validate_symbols`（符号名超长）、**发射期拒绝**（未识别 opcode） |
| `e_em5()` = 8022 | EM-5 条件跳转符号性不匹配 / 回绕运算误发溢出跳转 | `cmp_condition`、`is_wrap_arith` 判定、**发射期拒绝**（比较符号性与类型不符） |
| `e_em6()` = 8023 | EM-6 ABI 值形态不被当前 profile 支持 | `lower_ret`（切片或大于 8 字节聚合按值返回）、`lower_call`（大于 8 字节聚合按值实参） |

拒绝时 `EmitResult.ok = false`，`bytes` 为空，`rejection.kind` 标明拒绝类别。

### 发射期拒绝的传递路径

指令降级发生在函数粒度，拒绝信息必须沿装配链路上浮，不能就地吞掉：

```
lower_inst / lower_cmp  →  Emitter.rejected（首个被拒 opcode）+ Emitter.reject_kind（0=未识别, 5=EM-5, 6=EM-6）
                        →  FunctionLayout.rejected / reject_kind（copy_function 一并深拷贝）
                        →  ObjectLayout.rejected / reject_kind（build_layout 只保留首个，保证确定性）
                        →  emit_object 映射到登记码位并返回空 bytes
```

`reject_kind == 5` 映射 `e_em5()`，`reject_kind == 6` 映射 `e_em6()`，Win64 栈帧类别 7 至 9 映射 `E8006` 至 `E8008`，其余映射 `e_em4()`。因为只保留首个拒绝、且函数按 MIR 顺序遍历，
同一输入必然得到同一拒绝码，满足 `spec/proc/fixpoint.md` 的确定性要求。

Win64 在发射序言后直接核对编码中的栈调整和影子空间。函数体只写易失寄存器，固定尾声完整释放栈帧并恢复 `rbp`，正常返回和失败清理共用这套检查。驱动在终端或 JSONL 模式交付发射诊断，随后以失败退出。

x86 栈调整量在 `1..127` 使用 `imm8`，更大的正值使用 `imm32`。通用基址寻址选择可表示位移的最短字段，按基址决定零位移和 SIB。寄存器间接跳转及调用只编码实际需要的寄存器扩展位。Win64 序言针对等长的另一种寄存器传送形式发出 `E7102`，序言和尾声针对冗余的栈调整编码发出 `E7103`。

函数定稿从后向前删除可直接顺行到达目标的 `jmp`／`jcc`。相邻可删除分支按同一顺序合并，并保留跨越其它指令的分支及回边。剩余内部跳转先用 `rel8`，再逐轮扩展超出 `[-128, 127]` 的分支。定稿偏移同时用于 RIP 相对引用、内联跳转表、臂载荷桩、外部调用和静态数据重定位。连续对象发射和公开布局装配使用相同的定稿逻辑。

MIR `branch` 的任一边直达下一发射块时，顺行边省去跳转，由单条 `Jcc` 前往另一边。真边顺行使用 `JE`，假边顺行使用 `JNE`。两边同目标时省去条件测试，按无条件分支发射。

定稿后逐条解码函数的机器码，按指令形态消耗前缀、操作码、ModRM、SIB、位移和立即数。枚举分派在写入表时记录内联数据区，定稿重算边界，校验器仅越过紧随间接跳转的完整表项。子集外指令返回 `E7101`，等长的寄存器方向替代返回 `E7102`，可省的前缀或较长的操作数编码返回 `E7103`。指令编码参考 [Intel 指令手册第 2 卷](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)。

清除无效的 REX 位后，仍需扩展寄存器、操作数宽度或低字节选择的编码等长，发 `E7102`。整个 REX 可以省略时发 `E7103`。

寄存器直寻址及仅使用隐式栈地址的指令不受 `67` 影响。对普通访存，64 位模式下忽略 ES、CS、SS、DS 段覆盖字节。扫描器解码完操作数再报 `E7103`，同时出现等长别名时优先报可缩短形态。FS／GS 段覆盖和带旧段前缀的控制转移发 `E7101`，因为相同前缀字节可具有实际寻址或控制语义。

近 `CALL`、`JMP`、`Jcc` 与 `RET` 使用跨处理器一致的 64 位模式编码，禁止操作数宽度前缀 `66`。解码遇到这些形态时，在读取位移或核对重定位字段前发 `E7101`。例如，带 `66` 的直接 CALL 在 Intel64 与 AMD64 的指令边界可能不同。栈数据指令自身的 16 位操作数仍按各指令规则解码。

SIB 访存的默认段按完整基址寄存器判断，RBP 和 RSP 使用栈段，R12 和 R13 使用数据段。R12／R13 的无基址 ×1／×2 索引可改用基址，能缩短位移时发 `E7103`，只能选定等长规范形式时发 `E7102`。两个可交换的数据段寄存器中优先把 R13 放在索引位，以避免基址编码强制写零位移。涉及真实栈段的访存保留基址方向。

累加器绝对 `MOV` 在低 4 GiB 使用 `67` 与 `moffs32`，高地址若可由 `disp32` 符号扩展表示则使用绝对 SIB，其余地址使用 `moffs64`。同时需要 16 位操作数与 32 位地址时按 `66 67` 排列前缀。长形态发 `E7103`，前缀倒序发 `E7102`。地址宽度选择保留原访存数据宽度和方向。

无基址、无索引的绝对 SIB 访存在 `0x80000000` 至 `0xffffffff` 使用 `67` 零扩展地址。相同的 `disp32` 在默认地址宽度下表示符号扩展后的高端地址。低 2 GiB 的两种地址宽度产生相同的地址，带 `67` 的形态发 `E7103`。其它带 `67` 的实际访存仍受定稿指令子集限制。

单一基址且有效位移为零的 `LEA` 可用同宽寄存器 `MOV` 表达。带 SIB 或位移的长形态发 `E7103`，等长的直接基址形态发 `E7102`。生产栈取址在零位移时直接传送 RBP。8／16／64 位寄存器自传送及等价的 16／64 位自取址选单字节 `NOP`，长形态发 `E7103`。32 位自传送仍清零高半部。

16／32 位 `LEA` 只保留有效地址的低位，地址宽度前缀 `67` 可省。带 `67` 的 64 位目的 `LEA` 可用无地址前缀的 32 位目的 `LEA` 零扩展结果。RIP 相对形式也适用，已定值的位移按新指令末端修正，符号引用由 COFF `REL32` 或 ELF `PC32` 在新字段位置确定基准。定稿扫描以 `E7103` 拒绝这些长形态。

无基址、无索引的 16／32 位 `LEA` 直接用 `MOV r16, imm16` 或 `MOV r32, imm32` 装入常量，保留原标志位，并分别保留或清零目标寄存器的高位。定稿扫描对这类长形态发 `E7103`。默认地址宽度下的 64 位绝对 `LEA` 产生符号扩展的 64 位地址，其同宽立即数传送按规格使用 `imm64`。

立即数移位先按操作数宽度屏蔽计数。有效计数为零的寄存器移位可缩为 `NOP`，32 位目的用同寄存器 `MOV` 保留高位清零，两者均保持标志位。内存操作数仍保留访问，编码仅清除计数的被屏蔽位。

分支压缩后，调用与数据引用按定稿偏移与指令边界核对。直接调用的位点必须落在 `CALL rel32` 位移开头，静态函数和数据取址的位点必须落在 RIP 相对 `LEA` 位移开头，重复、越界、指令不匹配或落入跳转表均报 `E8004`。没有待链接重定位的 16 位 RIP 相对 `LEA` 使用符号扩展的低半字作为规范位移，等长别名报 `E7102`。待链接字段及加数则留给目标格式处理。

定稿扫描直接从实际字节收集剩余长分支，和发射阶段共用短优先、超界后扩展的尺寸计算。互相跨越的分支若能联动缩短、任意 `jmp`／`jcc` 指向紧随其后的指令，或相邻 `Jcc`／`JMP` 指向同一地址，报 `E7103`。已定值的分支目标落在参与缩短的分支内部时拒绝。错配的链接重定位先报 `E8004`，扫描所需临时数组的分配错误沿 `AllocError` 传播。

同一寄存器自异或、自减，以及寄存器和非负掩码的 `AND`／`TEST` 可使用 32 位操作，保持完整寄存器和定义的标志位。定稿扫描对可省掉整个 REX 的宽形态报 `E7103`，对仍需 REX 的等长 W 别名报 `E7102`。寄存器 `TEST` 使用 0 至 127 的掩码时取字节形态，128 至 32767 时取字形态。两种缩窄都使结果的符号位恒为零。内存 `TEST` 保留读取宽度。无符号除法发射使用可缩窄形态进行清零和取低位。

8／16／64 位寄存器的 `AND reg,reg`、`OR reg,reg`、全一掩码 AND 和零掩码 OR 等价于同宽 `TEST reg,reg`，两者保持寄存器值和已定义的逻辑标志。等长形式发 `E7102`，可缩短形式发 `E7103`。32 位写回需要清空高半部，内存读改写需要保留实际写入，因此两类操作继续使用其原有语义。

寄存器 `AND` 零掩码使用自异或清零，字节和字目的仍保留没有写入的高位。32／64 位目的共用 32 位清零原语。累加器字节立即数为等长别名，其余较长的 AND 零编码发 `E7103`。内存 AND 零保留完整的读改写。

同一寄存器 `CMP` 的差值恒为零，所有操作数宽度产生相同的六个算术标志。发射器与定稿扫描共用宽度规则，优先使用低字节，SPL、BPL、SIL、DIL 对应的自比较使用无需 REX 的 32 位形态。等长替代发 `E7102`，可缩短的形式发 `E7103`。

`MOVSX` 和 `MOVZX` 从 16 位源扩展时只接受 32 位或 64 位目的。16 位目的 `MOVSXD` 若读取内存，Intel64 与 AMD64 的读取宽度不同，定稿报 `E7101`。寄存器源只传送低 16 位，仍按普通 `MOV` 的等长别名报 `E7102`。32 位同宽装载与带 `REX.W` 的正常 32→64 位符号扩展继续按各自宽度校验。

拒绝类别必须与拒绝 opcode 配对记录：`em.rejected == 0` 是唯一写入条件，`unsupported_inst`（类别 0）、`reject_signedness`（类别 5）、
`reject_abi_form`（类别 6）三处都只在首次拒绝时同时写入 `rejected` 与 `reject_kind`。若 opcode 保留首个而类别被后来的拒绝覆盖，
同一函数内先出现未识别指令、后出现 EM-6 形态时就会误报 `e_em6()`，拒绝理由与实际首个失败点不符。
该配对不变量由定向用例覆盖：一个函数先命中 EM-6 形态（超限聚合复制）、随后命中 EM-4 形态（162 臂载荷），必须得到 `e_em6()` 与 `reject_kind == 6`。

## 边界与缺口

- 不重新解释 Yak 语义；类型宽度来自 `typecheck::TypeTable`，布局以 `spec/target/layout.md` 为准。
- 不做寄存器分配与指令选择优化（属 full 阶段）。
- 链接由外部 `ld` 完成。
- 已实现：`const_bytes` 与字符串字面量的 `.rdata` 落盘、数据符号、`lea` 相对重定位，
  以及 `&[u8]` 实参按 (指针, 长度) 展开（见上文「静态字节池与 `&[u8]` 视图」与「调用」）。
- 已实现：`call_far`(145) 的降级（跨单元 `ImportRef` → 合成高位键 → 外部符号重定位）与形参序言回填；
  `tools/link.sh` 按依赖顺序为每个单元产出 `.obj` + `.iface`，`gcc` 合并全部对象，故带参跨单元调用已原生贯通。
  MIR 与 YSM 的 145 编码（`b=ExportId`、`c=DependencyId`）保持规格冻结，不因发射层适配而改写。
- 已实现：`load`(80) / `store`(81) / `field_addr`(82) / `index_addr`(83)、`struct_construct`(96)、
  `array_construct`(97)、`move`(112) / `copy`(113)、`drop`(115) / `call_builtin`(146) 的降级，
  聚合局部按 `layout` 真实字节尺寸向上取整到 8 字节分配栈槽。
  `load` / `store` 对直接存储槽按值复制，对字段及索引生成的地址局部则间接访问；验证器要求直接槽与指令类型一致。
  `copy` 与 `move` 对切片局部搬运胖指针两个字（`[rbp-N]` 指针与 `[rbp-N+8]` 长度），
  避免只搬指针导致长度字段丢失。`call_builtin` 当前只承接 `@len`（`BuiltinId` 20486），
  从切片槽高 8 字节读取长度。
  栈槽位移在内部以正数表示，聚合内偏移经 `pe::load_slot_off` / `store_slot_off` 折算为 `-(slot - off)`，
  避免「槽位移 + 偏移」被当成无符号正数编码而写到错误地址（该缺陷曾使结构体字段读回 0）。
- `enum_dispatch`（177）已接通：以 tag 为索引读取函数内联的相对跳转表并 `jmp r64`，表项为 i32
  「目标块偏移 - 表基址偏移」，与目标同处 `.text`、零重定位；表项在函数全部块布局完成后统一回填。
- `enum_construct`（176）与 `carrier_ok` / `carrier_err`（160/161）已接通：先按 8 字节块清零目标槽，
  再按布局写入 tag 与 payload；payload 按精确宽度（8/4/2/1 组合）搬运，不用 8 字节读写越过对象尾。
- `carrier_dispatch`（162）的 tag 分支与臂载荷装载已接通：成功/错误臂把载体 `payload_off` 处的载荷按精确宽度写入臂块隐式局部，
  再跳目标块；无载荷臂直接跳转。
- `enum_dispatch`（177）的臂载荷桩：有载荷的臂在跳转表项中指向一段装载桩（取 `payload_off` 处载荷、写入隐式局部、再跳臂块），
  表项写「桩偏移 - 表基址偏移」，仍为零重定位自相对。
- 动态数组：`T[]` 槽占 24 字节头（ptr/len/cap）；`dyn_push`（178）取头地址、元素槽地址与元素尺寸，
  调用运行时 `yak_rt_push`，成功后载体写 tag 0、失败写 tag 1 与 `AllocError::OutOfMemory`；
  `@len` 读头内 `len`；索引按 `ptr + i*stride` 取址并以头内 `len` 做越界 trap。
- 析构（115）对动态数组调用 `yak_rt_free(ptr, cap * stride)`。本地结构体、定长数组、枚举、错误集与可错载体共用 `.rdata` 布局描述，在运行时逆序释放成员或只析构活跃分支。导入结构体按接口字段摘要逆序释放。
- 克隆（114）将目标布局描述附加到 `.rdata`。运行时按字段和元素深克隆，只读取枚举活跃载荷，失败时逆序回滚已构造部分并返回 `AllocError::OutOfMemory`。枚举与错误集的析构复用描述。
- 动态数组的 `.len` / `.cap` 与切片的 `.len` 读取头部对应机器字；仅用于本次读取的临时动态数组在读取完成后释放。
- 内建运行时符号（`yak_rt_push` / `yak_rt_free`）只在模块确实出现 178 或动态数组类型时追加到链接表，
  使用高位合成 DefId（`rt_symbol_*`），既有对象的符号表与字节布局不变。
- 普通引用和投影实参使用指针，切片使用两字槽，`Write` 实参传递已校验的 `out` 槽位地址。
- 函数静态引用用 RIP 相对重定位取本地或导入函数地址。间接调用复用 Win64 实参和返回布局，实参落位后经寄存器调用，支持栈传参、隐藏返回缓冲区与 `out`。
- 聚合按值 ABI 已按 Win64 规则接通（`abi-win.md` 2.7 / 2.8）：尺寸为 1/2/4/8 字节的聚合走寄存器；
  其他尺寸按调用方副本指针传参，返回走隐藏缓冲区（`rcx` 传入、`rax` 返回指针），被调方入口把指针
  指向的副本复制到自身栈槽。示例与链接端到端断言见 `examples/aggregate_abi.yak`。
- 顶层 `const S: &[u8] = "..."` 的全局常量视图已落盘并经端到端链接用例打印验证。切片实参可随其他参数进入 Win64 的寄存器及栈参数区。
- 当前实现以 EM-6（8023）失败关闭的剩余形态：切片按值返回；`foreign` 调用的按指针聚合实参
  （外部 C 函数可能改写调用方对象，必须传副本，本实现不分配临时副本）；
  以及单次聚合复制超过 4096 字节（栈槽模型按 8 字节块展开复制，超出上限拒绝以限定代码体积）。
  这些拒绝均不隐式降级为引用或截断搬运。返回视图切片在解析期已按 P-9（2009）拒绝，发射器该分支属纵深防御。
