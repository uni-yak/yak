# compiler/min/src/check

## 职责与边界

本目录把 base AST 转为稳定的作用域、引用、类型和布局事实。规格真源是 [name](../../../../spec/lang/name.md)、[symbol](../../../../spec/lang/symbol.md)、[base](../../../../spec/lang/base.md)、[layout](../../../../spec/lang/layout.md) 及各类型规格；本目录的通过结果不代表完整语言检查器已经完成。

解析 AST 保留声明名称和语法来源，引用身份由侧表给出。后端不得重新按拼写解析名字，也不得把 `NameId` / `ScopeId` 带入公开 MIR。

## 名称与引用

- 模块根作用域为 1；函数作用域登记参数及函数体顶层绑定，函数体不额外套块作用域。嵌套条件体与循环体建立块作用域，match arm 有独立绑定作用域及其体块。
- `DefId` / `ScopeId` 从 1 开始，按源码前序登记；`block_scope` 把 AST 块索引映射到实际作用域。绑定表按 `(scope, NameId)` 排序并回填区间。
- `ResolvedRef` 以节点类别和节点索引为键，保存 DefId、BuiltinId、ImportRef 或标签身份。原语专用表达式也必须登记 BuiltinId，不能让后端按 AST 数值补做名字解析。
- 前向引用按声明位置检查；直接调用 function / foreign 时允许 callable header 例外。已覆盖 N-1 / N-2 / N-4 / N-6 / N-7 / N-9 / N-10 / N-11 与 EN-1。
- 本地及内置 enum 标签、导入函数 / 类型 / 标签 / pattern 都由引用侧表和 bridge 记录连接。内置 enum 成员表由生成器提供。

## foreign 服务身份

引用解析器按原始 logical name 字节精确匹配已登记服务，随后按已解析的 builtin 类型与精确切片能力校验固定签名。参数名称不影响身份，`foreign #name` 与普通 foreign 共享 logical 服务名。

`Resolution.services` 按 foreign 声明序保存 `{ def, kind }`，其中 def 来自预登记结果；非法名称或错误签名发出 F-1（8001），服务种类为 0。函数签名复制该身份到 `FuncSig.service`，MIR 不得按相似签名猜测服务。

基础服务及宿主扩展以 [foreign](../../../../spec/lang/foreign.md) 和 [host](../../../../spec/proc/host.md) 为准；其中 `exit` 参数是 `u8`，`read` 返回 `u32`。内部运行时服务不因同名或同签名而向用户开放。

## 类型事实

- `TypeTable` 归一 void、内建类型、本地 / 导入名义类型、引用、切片、动态 / 定长数组、函数引用、fallible、nullable 和 ErrorSet。`TypeId` 从 1 开始；0 表示未知，不能作为后端默认类型。
- `FuncTable` 保存 DefId、参数 / 返回 TypeId 及已验证的服务身份；`DefTypeTable` 保存参数、局部和模块常量等定义的类型。字段和 enum payload 有各自的表。
- `ExprTypeTable.items` 按 AST 表达式索引记录实际 TypeId，包括模块 / 局部常量初始化、整数字面量、标量操作、调用参数与结果、enum payload、carrier 传播。原语 callee 不作为普通有值表达式。
- 无后缀整数只按唯一上下文定型；已知的另一侧操作数可反向提供类型，不选择默认整数宽度。显式整数转换目标可提供字面量上下文；两个无后缀整数直接比较时报告 E5005。数组中的已定型元素可反向定型其前方由无后缀整数字面量、负号、整数二元运算及嵌套数组构成的纯表达式。其他未定型场景尚未完整诊断；真实二进制接口的枚举构造会校验载荷数量和类型，结构体字段访问和构造会使用字段签名检查类型及字段集合。手工接口缺少签名时仍保留未知类型行为；导入结构体的后端字段访问与按值调用、导入枚举的 `match` 与构造已接入直接依赖的布局摘要、字段偏移与变体表，跨依赖错误集身份映射和导入结构体构造仍不完整，不能将类型检查无诊断视为跨模块类型安全。
- 已检查局部初始化、赋值与普通调用实参的一致性、条件 bool、普通和可错返回、enum payload 数量与类型，以及本地和导入枚举 match 的完整路径与裸标签的载荷绑定、宿主身份和已知标签穷尽性；裸标签身份暂不写回引用侧表；MIR 对导入枚举按 `(dep, export_id, 成员名)` 在变体表回查声明序，本地标签继续使用成员表。其余依赖接收方引用身份的后端形态，包括 `@move` / `@copy` / `@drop` / 回绕算术的相应类型、`@clone` 的 `T!AllocError` 结果，以及 `?` 的 carrier 目标与错误集子集关系，仍按本条限制。
- match 的已知标量、引用、本地及直接导入结构体 scrutinee 报 E6001，已知可错、可空及错误集报 E2012；导入结构体按依赖和导出身份判断，未知导入身份及泛型参数尚不能完整判定是否为 owning enum。
- 顺序比较只接受同一整数类型或 `char`；两侧类型已知时，不匹配或不允许排序均报告 E5001。MIR 验证器复用该类型规则，不依赖枚举载荷或导入签名。普通引用、切片（含字符串字面量）、定长及动态数组、本地有字段结构体和直接导入结构体的相等和不等比较也报告 E5001；函数引用的相等和不等比较仍允许；导入结构体按依赖和导出身份判定，不依赖字段签名。本地枚举直接或经本地嵌套枚举含定长数组、动态数组、本地有字段或直接导入结构体载荷时，其相等和不等比较报告 E5809；直接导入枚举的已知定长数组、动态数组或同依赖已导出结构体载荷也会使相等和不等比较报告 E5809，并经本地枚举载荷传播；同一依赖的导入枚举之间也传播这些已知载荷；缺失签名不作推断，其他不可比较载荷及跨依赖间接身份仍未完整验证，不能将同类型比较均视为合法。
- 诊断引用现有登记：P-4（2004）、P-5（2005）、R-1（5001）、EN-2 / EN-3（5804 / 5805）、RE-8（5811）。

`const.yak` 在类型检查末尾求值 base 常量：整数按目标位宽掩码、`bool` / `char`、Copy enum 标签与 payload、`[T; N]` 定长数组、整型二元与一元运算、静态 `&[u8]` 字符串视图；物化规则只放行可 Copy 的递归常量值与完整顶层 `&[u8]`，其余按 C-1（5006）/ C-2（5007）拒绝。求值只读类型表快照，不改动检查结果。已求值的枚举与定长数组常量由中端按布局落成类型化的只读静态池条目并进入数据节；`&[u8]` 常量继续走常量字节视图。检查阶段本身不发射字节。

数组及切片索引支持一层数组引用的元素类型推断；已知非数组和非切片宿主或非整数下标在类型检查时报告 E5001，未知类型不追加猜测性诊断。定长数组及其单层引用在类型推断后检查编译期可证的索引越界（E6002）：支持无后缀整数及负字面量、已定型的整数字面量和可求值的 base 常量表达式，以及索引根部连续整数转换链；转换按源类型符号扩展和目标类型截断。动态数组和切片（含单层引用）对可证的负下标也报告 E6002，但不猜测运行期长度。动态表达式或试算失败不产生额外诊断。试算复用常量绑定并将中间值追加到常量表，不改变既有绑定；临时值目前保留至检查结果销毁。连续转换链的已知和未知试算结果在一次类型检查内共享缓存，避免重复遍历链和重复求值链底。未定型复合表达式、非连续转换表达式以及切片和动态数组的其他编译期越界检查尚未完整覆盖，不能视为 R-3 的完整实现；E5004 目前仅覆盖已定型非负整数常量到更窄整数且可求值高位非零的转换；负数、未定型源与非连续转换表达式等尚未完整覆盖。引用数组的运行期后端支持另有限制。

`as` 白名单与 `match` 穷尽性已实现：白名单按各类型文档的转换章节（整数互转、`char`↔`u32`），对可试算的 `u32 as char` 在代理区或超过 Unicode 最大标量时报告 E5001；动态值、试算失败及非连续转换等未知情形不作额外判断，不能视为完整的运行期标量有效性保证。`match` 覆盖标签重复、`_` 位置、标签归属与缺臂判定。未知类型不得被后端改成任意标量；不支持的形态必须明确拒绝。布局模块和后端另行验证其输入边界。

### 可空载体前端

显式可空入口依次使用 `lex_scan_nullable`、`parse_lexed_nullable` 和 `verify_nullable_frontend`。类型检查在预期 `T?` 中接受 `null` 和类型恰为 `T` 的 present 表达式，检查 `??` 的回退类型以及 `?.` 字段投影。`E5813` 覆盖缺少可空上下文或载荷类型非法，`E5814` 覆盖非可空接收者，`E5815` 覆盖可空后缀传播、错误恢复和普通联合分流，`E5816` 覆盖裸组合后缀、未初始化存储与显式状态伪造。`t435` 验证精确位置与诊断优先级。MIR 控制流、可空调用和运行期活跃载荷的所有权接线仍待完成。

### 普通联合与字符串前端

`lex_scan_plain_union`、`parse_lexed_plain_union` 和 `verify_union_frontend` 启用普通联合检查。类型表展开成员分组并在单元内规范化，布局复用带标签载荷。测试覆盖相同成员不同书写顺序、成员注入、直接 `if value is T` 收窄和 `E5817`–`E5820`。跨单元成员序、MIR 标记与活跃载荷管理待接入。

`lex_scan_text`、`parse_lexed_text` 和 `verify_text_frontend` 启用 `string` 与 `&string`。前者使用拥有数组布局，后者使用只读借用视图布局。类型检查允许从拥有值借用、在预期的借用类型中接收 UTF-8 字面量，以及显式转成字节视图。对 `&string` 执行 `@move`、`@drop`、`@clone` 时报告 `E6204`。受检构造、借用生命周期和目标发射待接入。

### 泛型函数签名

`resolve_refs::read_generic_signature` 显式读取含类型参数的 TypeSig，复用普通接口签名的根槽和名义身份校验。`monomorph::instantiate_signature` 接收显式实参、已定型的调用参数、可选目标类型和已解析的接口约束事实。推导经过数组、引用、函数引用及载体子类型。组件把所有参数代换为同一单元 `TypeTable` 内的具体类型，并核对替换后的使用位置。无解时在调用位置给出唯一 `E3007`，返回空实参与形参列表以及零返回类型。泛型源语法、名义泛型实例、实例体生成及跨单元去重属于后续管线接线，当前 base 入口继续拒绝泛型。

## 所有权与借用

`owner.yak` 以 `DefId` 为键维护 place 状态（live / moved / dropped / empty）。`is_copy_type` 对 struct 按字段表、对 enum 按 payload、对 `[T; N]` 按元素递归判定；可错载体按成功类型和错误集的全部成员递归判定。`T[]`、`T?` 与导入名义类型保守判为非 Copy。

已落地规则：移动后继续使用报 R-4（`E6003`）；`@drop` 语句与 `@move` / `@drop` 实参消费 place；`@copy` 对非 Copy 操作数报 R-20（`E6202`），`@clone` 对 Copy、视图及可错／可空载体报 R-21（`E6203`）；它们与 `@len` 等一样读取源；普通实参按值传递转移 owning 所有权；借用记录 owner、能力与作用域；`out` 槽位未填满读取报 R-19（`E6102`）；显式临时 `ReadWrite` 借用直接 `var` 根后，同一完整表达式内访问该根或其投影报 R-5（`E6004`）；对直接 `let` 位置请求 `ReadWrite` 报 R-15（`E6009`）。消费后不再递归读取同一表达式，避免把一次移动误报成移动后使用。

本地普通函数直接调用的 `&T:Read` 实参以 `T` 为定型上下文，接受 `T`、`&T:Read` 或 `&T:ReadWrite`，保留表达式实际类型，不移动拥有值；实参内部的所有权检查照常执行。此规则不扩展到 foreign、导入或函数引用调用。绑定引用的块级租约、活跃 `Read`、引用或切片别名根、静默 `ReadWrite` 及原生降级仍未覆盖。

下标或切片边界的求值、投影赋值右侧的求值若使已定位的直接宿主失效，随后的访问或写回报 R-4（`E6003`）；整根赋值仍可重新初始化。

部分移动已按 OW-10 拒绝（`E6205`）：owning 类型的成员（kind 23）、索引（kind 24）与切片（kind 27）投影出现在 `let` / 赋值初始化、`return`、聚合分量、`@move` 实参等值转移位置时一律报错，不区分宿主是绑定、临时值还是常量；`match` scrutinee 只读取整体，不在此列。整根 owning 移动与 Copy 字段读取保持合法。宿主的 place 状态不被部分移动消费。

析构已按 OW-11 收紧（`E6206`）：`@drop` 只接受整 place，成员、索引与切片投影一律拒绝，且不区分投影类型是否为 Copy；语句形式与表达式形式都按同一规则判定。这与 seed 参考解释器的「requires a whole place」一致，同时避免 MIR 先读取投影再对根重复析构。

`OwnerResult.drop_plans` 按函数和源码位点登记逆序析构计划，覆盖显式返回、`?` 传播、`break`、`continue`、块落尾与隐式返回。函数退出包括拥有型按值形参，块级和跳转计划只覆盖退出的作用域；借用、`Write` 形参与已确定失活的绑定不计入。仅部分前驱仍持有的整值进入条件析构计划，MIR 维护守卫；checked 算术与下标／切片的当前帧陷阱按指令位置计算活性并回滚满槽，边界见[所有权规格](../../../../spec/lang/owner.md)。

源码错误集成员在名称解析后核对类别：接受本地和导入 enum 以及固有 `AllocError`，已解析的非 enum 发出 E5807；未解析名称保留名称解析诊断。成功位直接引用与错误成员相同的枚举时发出 E5802；此检查按当前解析身份比较，不解决跨接口身份重映射。内存错误集至运行时布局的规范身份排序和跨模块依赖映射仍未完成；接口 TypeSig 的本地子集见下文。

## 布局、模块与接口

布局模块覆盖标量、视图、数组、struct、enum、ErrorSet、fallible 和 nullable 的 yak64-v1 布局，计算字段 padding 与尾部对齐，并检查按值依赖环。导入名义类型按被导入接口的布局摘要取 `size` / `align`：驱动把直接依赖的摘要装入 `ImportedLayoutTable` 后调用 `layout_unit_with_imports`；传递依赖的摘要在候选裁剪时不保留，缺失摘要的导入类型保持 `known=false`，不伪造大小。按值依赖未知成员的错误集与结构体同样保持未知，不将未知字段误报为零尺寸。类型检查把已载入接口的字段签名按 `import_slot_type` 重映射为消费方 `ImportedFieldTable`（`(dep, export_id, 1 基字段序, TypeId)`）；`imported_field_layouts` 再用 `imported_field_offset` / `imported_struct_size` 生成逐字段偏移表，并与摘要尺寸、对齐交叉校验，任一项缺失或不符时整组 `known=false`。MIR 与 COFF 只消费该表，缺偏移即拒绝，不按零偏移回退。枚举变体同样经 `ImportedEnumTable` 重映射（`(dep, export_id, variant, payload TypeId, known)`）；布局阶段按变体载荷推导 `tag_size` / `payload_off`，并与摘要尺寸、对齐交叉校验，缺签名或不符时保持未知。MIR 的导入 enum `match`、构造与验证只消费该表，COFF 的跳转表与 tag/payload 搬运复用同一布局结果。

模块图按完整 import 路径字节建立依赖边，检查模块重名、自导入、缺失依赖与循环，按确定性 DFS 后序输出依赖优先序。引用解析对同一 import 匹配多个接口身份时报告 E4003 并保持未绑定；当前接口集合的位置编号上限为 65535，匹配位置超过该实现资源上限时报告 E9001 并保持未绑定，避免截断错绑。驱动只为源码直接导入的接口分配编号，按接口摘要和完整模块名排序；非直接候选通过容器校验后只保留身份。

接口模块已实现 SHA-256、递归前缀 TypeSig、函数签名、YKIF format 2 容器、enum / struct 描述符与布局摘要，以及 `add_binary_dependency` 到 resolver 的适配。载入时先校验目标 profile、节目录、固定记录尺寸和重叠，再核对摘要及模块、导出和成员名称 / 签名范围，读写均校验模块完整路径各段为当前参考组件支持的 ASCII 标识符、排除保留字和占位字；写出时还拒绝超过 65535 字节的身份，避免长度截断。非 ASCII 名称字符分类尚未冻结，因此暂不支持；无效接口返回空接口并发出 S-12，超出签名深度资源上限则发出 E9001。导出记录校验名称哈希、严格排序和连续编号，导出、枚举成员与结构体字段的名称须为当前参考组件支持的 ASCII 标识符，并校验名称哈希；布局摘要先校验归属、顺序及格式，再为当前支持的非泛型 struct / enum 复算 yak64-v1 布局，按声明顺序计算字段 padding、标签、载荷与请求对齐，拒绝按值环、溢出及不符的摘要；复算不依赖输入摘要作为中间值；导入名义类型的布局已按直接依赖摘要接入检查阶段，其**成员存储签名**（结构体字段与枚举载荷）现可编码为依赖名义标签并在载入时解码（要求目标带正尺寸/对齐摘要），但 MIR 的字段访问、构造与按值使用仍失败关闭；类型导出按节内偏移与同类描述符一一对应，检查成员范围、泛型摘要哨兵、摘要所属类型及请求对齐；成员和字段表校验宿主、编号顺序及与描述符区间的一致性，检查枚举载荷标志与签名长度，并校验名称索引的指向、严格排序及完整覆盖；已加载的导出、布局、描述符、成员和名称索引记录会校验支持的标志及保留位；泛型体索引校验导出关系、顺序、保留位和函数体范围；函数体内容尚未校验或接入。加载器验证依赖节记录、名称格式及顺序。驱动在解析成功后核对每条直接导入接口的依赖记录：若提供同名候选，摘要必须一致；若只找到同摘要异名候选，报 E7012；标量导入仍允许未提供传递目标。尚未实现跨接口 TypeSig 的依赖编号重映射，签名中的依赖名义类型暂时拒绝；公开函数、字段和枚举载荷的签名写出也暂拒导入类型，以免生成缺失依赖身份的接口。加载时校验泛型与非泛型函数的完整签名字节，复用类型位置和名义目标检查；类型参数编号必须小于签名元数，不得作为错误集成员。此处不验证泛型函数体；T1 导入解析仍拒绝非零泛型元数，不支持泛型调用或实例化。字段和枚举载荷会按普通存储位置解码并完整消费签名，复用函数签名的名义目标和错误集检查；当前暂拒泛型描述符及包含无法映射的依赖名义类型的成员签名。描述符关系、其他记录排序及 TypeSig 的完整语义校验尚未全部实现。载入函数导出时保留已校验的 no_alloc 位，并经依赖集合复制到实际引用的桥接记录；驱动在 MIR 分析成功后按 DefId 传递推导结果，严格写出入口对缺失或非法事实拒绝产出；MIR 导入分析按依赖和导出身份使用该位。兼容入口仍只写保守零标志，不供驱动替代严格入口。公开签名引用未导出的本地名义类型发出 N-8。写出阶段存在错误诊断时返回空数据、空摘要和零导出数，不封装部分签名或描述符。

接口写出和导入的字段、枚举载荷、函数参数及返回类型，每条 TypeSig 的根到叶路径最多允许 64 个类型节点（根计 1）；超出该实现资源上限时报告 E9001 并拒绝该签名，即使其格式本身符合规格。不同形参及返回类型分别计数，此限制用于避免不可信接口耗尽递归栈。函数及函数引用的形参数超过格式所能编码的 65535 时报告 E9001，避免截断；函数引用成员区间越界时报告 E7012。编码可错类型时校验错误集类型、1–65536 成员数及成员数组区间，拒绝无效类型编号、非名义复合类型、非 AllocError 的固有成员、已知同身份的成功类型重叠以及固有 / 本地 / 导入成员的重复身份，畸形内部表发出 E7012；真实 `.iface` 中，固有 `AllocError` 排在同模块零实参枚举之前；本地枚举按名称长度的 little-endian 字节和名称字节排序，加载器要求严格升序。函数和成员签名中的嵌套类型同样校验。无名称的手工签名仍按内部身份查重；YSM 编码维持内部顺序。

导入函数签名随 `DependencySet` 进入类型检查：`resolve_refs.yak` 的 `load_import_signatures` 仅对成功绑定的直接导入、按接口集合原编号和与 `encode_type` 对称的字节布局解码每个函数导出的 `sig_off` / `sig_len`，把形参区间与返回槽存入 `RefTable.imports`；`typecheck.yak` 的 `import_slot_type` 再映射为本地规范类型，导入调用点据此逐参校验并取回真实返回类型。导入函数目前仅支持零泛型元数，遇到类型参数 opcode 时拒绝；普通引用使用 `0x07`，不把 `0x04` 当作引用。解码越界、定长数组长度为零、内建编号不属于 base 阶段已激活的类型符号（包括预留给 full 的编号）、类型实参数量非零（当前不支持）、出现尚无法映射身份的依赖名义类型、`void` 不在函数返回或可失败成功位、`AllocError` 不在错误成员位置、失败载体不在允许的返回或引用位置、失败成功位为函数引用、可空载荷为函数引用或另一可空类型、普通引用或切片不在顶层参数位置、函数引用参数不是普通引用、切片或函数静态引用、错误集成员不是名义类型、已知的固有 / 本地成员不是枚举或与成功类型身份相同，或本地名义目标不是有效的结构体 / 枚举导出时，报 S-12（`7012`）且不保存该签名。导出方本地名义类型按导出方依赖和导出编号映射，含复合类型内的引用；错误枚举拒绝当前可确定的固有或本地重复身份（含非相邻成员）；真实接口已执行上述子集的规范排序；间接依赖的错误成员身份及编号重映射、无法表达类型的完整拒绝尚未实现，接口桥接不等于所有导入类型语义均已完成。嵌套函数静态引用参数当前按语法产生式接受，但 `parse.md` 的 `ParamType ::= RefType` 与 `symbol.md` 的 function_ref 参数只能为 `ref` 或 `slice` 的编码约束存在分歧；最终合法性及接口行为待规格裁决，现有回归只证明当前实现行为。

## 管线与验证

`run_frontend` 聚合各阶段诊断，遇到错误停止并排序，返回是否通过；它不输出 MIR、YSM 或目标文件。MIR 构建入口独立消费检查后的事实，不能把前端入口退出成功当作编译产物证据。
